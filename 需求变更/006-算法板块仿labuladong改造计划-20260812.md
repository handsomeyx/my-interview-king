## 背景

**目标用户**：准备 Java 后端社招面试的开发者，算法是面试高频考察项，也是本站主要入口词之一。

**问题来源**：明确将 labuladong.online 列为算法板块竞品后，对其全站 sitemap 做结构拆解，并与本项目 `docs/algorithm/` 现状（35 篇）逐层对标，识别出可借鉴的内容组织方法与本项目独有的反超点。

**核心目标**：用 labuladong 的**内容组织方法**（框架→例题→习题三段式、按题型分阶、双学习路径）升级算法板块的结构与写作；同时放大本项目独有的**后端系统算法**（labuladong 不覆盖）作为差异化护城河。

**现状一句话诊断**：框架层（`00-algorithm-frameworks/`，9 篇 6000-8000 字）已经成型且扎实——这是最难的部分，已完成；真正缺的是"框架→习题"那座桥、基础层厚度、以及把独有的后端系统算法从子目录提升为招牌卖点。

## 战略前提：仿什么 / 不仿什么 / 靠什么反超

> 这是整份计划的红线，先定死，避免改造过程中触发新一轮越界（参见 `CLAUDE.md` 红线①与 `需求变更/004` 冻结清单）。

| 类别 | 内容 | 决定 |
|---|---|---|
| ✅ **仿** | 内容组织方法：框架→例题→习题三段式、按题型分阶（-i/-ii/-iii）、双学习路径入口、框架文每篇嵌 2-5 道例题 | 全盘学。这是方法论，与定位无关 |
| ❌ **不仿** | 可视化面板、算法游戏、多语言、在线判题 problemset、AI 助教、刷题插件 | **冻结**。这是 labuladong 的工程护城河，阶段一碰即越界（见 004 第 9/10 条） |
| 🏆 **反超** | `04-system-algorithms/`（缓存 / 负载均衡 / 限流 / 唯一 ID 等后端系统算法） | labuladong 是纯算法站，不讲后端系统设计算法。这是「Java 后端面试」定位的杀手锏，必须放大 |

**一句话原则**：学他的骨架（怎么组织算法教学），不学他的肉（工程化工具），用独有的脊柱（后端系统算法）站起来。

## 需求清单

### 批 1 · 打通「框架→习题」（最高优先，~1 周）

**问题场景**：用户读完滑动窗口框架文，想练手，但 `05-top-interview-100` 是按题型（数组/链表）而非按框架组织的，且无难度分阶。学与练脱节，形不成肌肉记忆。

**技术方案**：新增 `docs/algorithm/06-practice/`，按框架命名专项练习，每篇 5-10 道、可直接套对应框架。首篇结构：点名套哪个框架 → 5-10 题（题号 + 难度 + 一句话点出"框架哪一步变化"）→ 首题完整示范。

**目录草案**：
```
06-practice/
├── sliding-window-practice.md       ← 配 00/sliding-window
├── binary-search-practice.md        ← 配 00/binary-search
├── binary-tree-practice-i.md        ← 分阶：基础遍历
├── binary-tree-practice-ii.md       ← 分阶：后序/构造
├── dfs-bfs-practice-i.md
├── dfs-bfs-practice-ii.md           ← 网格/岛屿类
├── backtrack-practice-i.md          ← 排列/组合/子集
├── dynamic-programming-practice-i.md
└── dynamic-programming-practice-ii.md   ← 股票/背包/子序列
```

**涉及文件**：新增 `docs/algorithm/06-practice/*.md`；改 `docs/.vitepress/config.mts`（sidebar 增分组）。

**工作量**：大（9 篇，每篇含题解，约 1 周）。

**优先级**：P0。

### 放大反超点：`04-system-algorithms` 升级为招牌（~1 周）

**问题场景**：`04-system-algorithms/`（缓存 / 负载均衡 / 限流 / 唯一 ID）是本项目独有、labuladong 完全不覆盖的内容，但当前只是 algorithm/ 下的一个普通子目录，没有作为卖点被打出去。

**技术方案**：
1. 提升为**首页并列的一级卖点**（与「Java 后端」「算法」并列的「系统设计算法」）。
2. 补齐后端高频：一致性哈希、跳表、布隆过滤器、限流（令牌桶 / 漏桶）、分布式 ID（雪花）、LRU/LFU。这些既是"算法"也是"后端面试高频"，竞对要么不讲、要么讲得浅。

**涉及文件**：改/新增 `docs/algorithm/04-system-algorithms/*.md`；改 `docs/index.md`（hero features 增一项）；改 `config.mts`（sidebar/nav）。

**工作量**：中。

**优先级**：P0（差异化护城河，应与批 1 并行推进）。

## 框架文写作模板（落地参考）

> 改造 `00-frameworks/` 与新建 `06-practice/` 时统一遵循。当前 sliding-window 文已接近，仅差例题数。

```markdown
---
problems:        # frontmatter 挂题，供 RelatedProblems 组件读
  - title: ...
    url: https://leetcode.cn/problems/...
    difficulty: medium
---

# XX 框架

## 一、核心思想           ← 一段话讲清这类题的本质
## 二、框架模板           ← 可直接背的代码骨架（注释标"在这里做什么"）
## 三、适用场景           ← 3-5 条，告诉你什么时候套
## 四、例题 1（基础）     ← 完整：题目 → 如何套框架 → 关键变化点 → 完整代码
## 五、例题 2（进阶）     ← 同上，强调与例题 1 的差异
## 六、例题 3（变式）     ← 到 2-5 道为止
## 七、常见坑 / 复杂度
```

**关键**：例题不是"附在后面"，而是**嵌进框架**——每道题说清"框架的哪一行为了这道题变了"。这是 labuladong 的写法，也是本板块质量再上一档的关键。

## 规则呼应

本计划**完全是内容工作**：0 行后端代码、不碰判题、不碰可视化、不碰游戏、不碰在线运行。完全符合 `CLAUDE.md` 阶段一红线与 `需求变更/004` 冻结清单。换句话说，这是当前规则约束下算法板块 ROI 最高的升级路径。

# 需求变更文档

存放本站点所有需求变更与优化记录。每份文档应独立说明「为什么改、改什么、怎么改」，便于后续追溯与实施。

## 命名规范

`编号-简短主题-日期.md`

- 编号：三位数字，从 001 起递增
- 主题：中文简述，词与词之间用连字符
- 日期：YYYYMMDD

示例：`001-用户体验优化清单-20260811.md`

## 文档模板

每份文档建议包含以下小节：

1. **元信息**：编号、日期、来源、状态
2. **背景**：问题来源、目标用户、期望目标
3. **问题清单**：每条包含
   - 问题场景（用户视角复述痛点）
   - 技术方案（具体到文件、组件、API、数据结构）
   - 涉及文件
   - 工作量评估（极小 / 小 / 中 / 大）
   - 优先级（P0 核心痛点 / P1 重要 / P2 锦上添花）
4. **优先级总览表**
5. **实施建议顺序**（分批推进）

## 状态约定

草稿 → 待实施 → 实施中 → 已完成（或 已废弃）

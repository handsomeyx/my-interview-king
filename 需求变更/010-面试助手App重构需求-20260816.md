### 2.4 AI 接入方案

**核心原则：先 Mock，可插拔，便于后续切换真模型。**

```python
# services/ai_service.py

class AIService:
    """AI 服务门面，支持 Mock / 真实 LLM 两种模式"""
    
    def __init__(self, mode: str = "mock"):
        """
        mode: 
          - "mock": 使用本地关键词匹配（开发/演示用）
          - "llm": 调用真实 LLM API（生产用）
        """
        self.mode = mode
    
    async def chat(self, messages: list, stream: bool = False):
        """对话接口"""
        if self.mode == "mock":
            return self._mock_chat(messages)
        elif self.mode == "llm":
            return self._llm_chat(messages, stream=stream)
    
    async def analyze(self, question: str, answer: str):
        """分析回答质量 -> 返回信心指数 + 知识图谱 + 追问"""
        ...
    
    def _mock_chat(self, messages):
        """本地 Mock，保持与现有 server.py 兼容"""
        ...
    
    def _llm_chat(self, messages, stream=False):
        """调用 LLM API，流式用 SSE"""
        # 支持配置: Dify / 千问 / Kimi / 直连
        ...
```

### 2.5 SSE 流式通信协议

**后端（Flask SSE）：**

```python
# blueprints/ai_bp.py

@ai_bp.route('/chat/stream')
def chat_stream():
    """SSE 流式对话"""
    message = request.json.get('message', '')
    ai_service = AIService(mode=current_mode)
    
    def generate():
        for chunk in ai_service.chat_stream(message):
            yield f"data: {json.dumps(chunk)}\n\n"
        yield "data: [DONE]\n\n"
    
    return Response(generate(), mimetype='text/event-stream')
```

## 四、关键技术规格

### 4.1 Markdown 渲染要求

```
marked 配置项：
- gfm: true           ← GitHub Flavored Markdown（表格、任务列表、删除线）
- breaks: true        ← 换行符转为 <br>
- highlight: highlight.js  ← 代码高亮，支持 java/python/sql/bash
- 禁止 raw HTML 注入
- 代码块添加复制按钮
- 代码块超长自动横向滚动
```

### 4.2 SSE 事件格式

```typescript
// 前端解析的事件结构
interface SSEEvent {
    type: 'token' | 'done' | 'error' | 'meta'
    content?: string          // token 文本片段
    confidence?: number       // 信心指数（meta 事件）
    followUps?: string[]      // 追问建议（meta 事件）
    knowledgeGraph?: KGNode[] // 知识图谱（meta 事件）
    error?: string            // 错误信息
}

interface KGNode {
    name: string
    strength: 'strong' | 'medium' | 'weak'
}
```

### 4.3 请求/响应规范

```typescript
// 统一响应格式
interface ApiResponse<T> {
    code: number       // 0 = 成功, 非 0 = 错误
    message: string    // 错误信息
    data: T            // 业务数据
}

// 错误码
// 0: 成功
// 40001: 参数错误
// 40101: 未登录
// 40301: 权限不足（游客次数用完）
// 50001: 服务器内部错误
// 50002: AI 服务调用失败
```

### 4.5 数据库 Schema（MVP 保持 SQLite）

```sql
-- 对话表
CREATE TABLE IF NOT EXISTS chats (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    title TEXT,
    preview TEXT,
    created_at TEXT,
    updated_at TEXT,
    FOREIGN KEY (user_id) REFERENCES users(id)

-- 消息表
CREATE TABLE IF NOT EXISTS messages (
    id TEXT PRIMARY KEY,
    chat_id TEXT NOT NULL,
    role TEXT NOT NULL,  -- 'user' | 'assistant'

    FOREIGN KEY (chat_id) REFERENCES chats(id)

CREATE TABLE IF NOT EXISTS analyses (
    id TEXT PRIMARY KEY,

    follow_ups_json TEXT,       -- JSON 存储
    created_at TEXT,
    FOREIGN KEY (message_id) REFERENCES messages(id)
);
```

## 六、开发注意事项

### 6.1 不要做的事

1. **不要重写后端框架** —— Flask 继续用，按蓝图拆分即可，不要换 FastAPI/Django
2. **不要过度设计** —— Pinia 够用就不用 Vuex，SQLite 够用就不引入 Postgres
3. **不要造轮子** —— Markdown 用 marked、图表用 echarts、HTTP 用 axios
4. **不要改 VitePress 知识库站** —— 本次重构仅限 `frontend-interview-agent/`

### 6.2 必须做的事

1. **保持向后兼容** —— API 路径 `/api/chat`、`/api/login` 等不变，旧前端调用不受影响
2. **类型安全** —— 所有 props、emits、API 响应都要有 TypeScript 类型
3. **错误处理** —— SSE 断开要自动重连，API 401 要跳登录
4. **本地开发体验** —— `npm run dev` + `python server.py` 能一键跑起来

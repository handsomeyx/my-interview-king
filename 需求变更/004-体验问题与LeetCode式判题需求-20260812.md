## 背景

阶段 1 代码运行器上线（code-exec 容器内 javac+java），用户能跑 Java 代码。但评审发现距 LeetCode 式刷题体验仍有差距：只覆盖 Java、无判题、编辑器糙、代码不保存等。本文档整理 12 处不满 + LeetCode 式判题详细需求。

**从「能跑代码」升级到「能刷题验证」**——学算法的核心是验证对错（用例通过/失败），不是仅看输出。

### P0 核心（决定站点价值）

#### 1. 代码运行器扩展 Python（D4 解禁）
**问题**：当前仅 Java（D4 决策）。AI 板块 Python 代码、数据科学示例不能跑。
**方案**：
- Dockerfile 基础镜像加 Python3（`apt-get install -y python3` 或换含 Python 的基础镜像）
- `LocalExecutor` 加 python 分支：写 `.py` → `python3` 跑（无编译步骤）
- 前端 CodeRunner `RUNNABLE` 加 `python`
**涉及**：code-exec Dockerfile、LocalExecutor.java、application.yml、前端 CodeRunner

## LeetCode 式判题重点方案

### 数据模型（code-exec 加 PostgreSQL）
```java
Problem {
  id, slug, title, description,
  difficulty(EASY/MEDIUM/HARD),
  timeLimitMs, memoryLimitKb,
  template{java, python}
}
TestCase { id, problemId, input, expectedOutput, isSample, ordinal }
Submission { id, userId, problemId, language, code, verdict, passedCount, totalCount, createdAt }
```

### API
```
GET  /api/problems                 题库列表（分页、按难度/标签筛）
GET  /api/problems/{slug}          题目详情 + 代码模板 + 样例 case
POST /api/problems/{slug}/submit   提交判题
  请求: { language, code }
  响应: {
    verdict: AC | WA | TLE | RE | CE,
    passed: X/Y,
    cases: [{ idx, passed, expected, actual, timeMs }]
  }
```

### 判题流程
1. 用户提交代码
2. 后端取该题所有 TestCase
3. 每个用例：跑代码（stdin = case.input）→ 对比 stdout 与 case.expectedOutput（trim 后逐行比）
4. 全过 = **AC**；部分过 = **WA**（显示首个失败 case 的 expected vs actual）；超时 = **TLE**；编译错 = **CE**；异常 = **RE**
5. 持久化 Submission（阶段 3 接用户后归 userId）

### 前端题目页（LeetCode 式三栏）
- **左**：题目描述 + 样例
- **右**：代码编辑器（CodeMirror）+ 语言切换 + 「▶ 运行」（用样例）+ 「提交」（全部用例判题）
- **下**：结果区（verdict 大字、通过 X/Y、失败 case 的 expected vs actual 对比）

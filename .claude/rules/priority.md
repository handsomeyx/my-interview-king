# 优先级裁决清单

> 触发：不知道该做什么、或一个任务不直接推进北极星时读。
> 裁决从上到下，**命中即停**，不要往下找借口。

## 裁决顺序

1. [ ] **是否阻塞北极星？**（站点上线 / 被收录）
   - 是 → 立刻做。例：部署、域名、sitemap、robots.txt。
2. [ ] **是否在堵内容漏斗？**（Java 板块当前约 20 篇，距 G1 的 30 篇仍是最短板）
   - 是 → 写内容。例：补 Java 深度文章。
3. [ ] **是不是在重复造已有轮子？**
   - 力扣 / 牛客 / 代码随想录 / JavaGuide / 小林 coding 已经做得很好的功能 → **不做**。
   - 我们的弹药是深度内容，不是工程复杂度。
4. [ ] **是不是 5 分钟能顺手修的小瑕疵？**（typo、死链、CSS 数值）
   - 是 → 顺手做掉，单独提交。
5. [ ] 都不是 → 进 `需求变更/` 写个想法，**不动代码**。

## 投资者视角三连问（拿不准时用）

- [ ] 这件事一周后能看到用户价值吗？
- [ ] 不做会死吗？
- [ ] 做了之后，能和我们的定位（深度 Java 面试体系）形成正反馈吗？
- 三个都 No → 大概率不该现在做。

## 反面教材（本项目已踩过的坑）

- 路线图明写"阶段一不上线 frontend-interview-agent"，却去搭 Java 微服务判题 → 违反 1、3。
- Java 才约 20 篇（距 G1 的 30 篇还差），却要建 LeetCode 题库 → 违反 2、3。
- 几周不 commit，未跟踪文件堆积 → 任何"新功能"都该让位于"先把成果落袋"。

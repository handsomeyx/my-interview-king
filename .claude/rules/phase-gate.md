# 阶段门禁清单

> 触发：CLAUDE.md 红线①未通过时读。
> 目的：挡住"阶段一没做完，就开始卷阶段二三功能"——本项目当前最严重的病。

## 第一步：这个任务属于哪个阶段？

对照 `ROADMAP.md` 第三节，把任务归到下表某一栏：

| 阶段 | 标志性动作 |
|---|---|
| 一 | 部署上线、域名、SEO、统计、产出文章 |
| 二 | 账号体系、SQLite→Postgres、用户工具上线、主站 CTA 导流 |
| 三 | 支付、会员分级、AI 模拟面试、付费题库 |

## 第二步：当前在阶段一。逐条 gate：

- [ ] G1 退出条件全部达成？
- [ ] 这任务本身是阶段一的事？
- 两条都 No → **停**。把想法记进 `需求变更/` 或 issue，回到阶段一任务。

## G1 · 阶段一退出条件清单（全部 ✅ 才算阶段一完成）

- [ ] 站点已部署（Cloudflare Pages / Vercel），可公网访问
- [ ] 已绑定自定义域名 + HTTPS
- [ ] `sitemap.xml` + `robots.txt` 已生成
- [ ] 已提交 Google Search Console + 百度站长平台
- [ ] 已接入统计（Umami / Plausible / GA）
- [ ] 内容 ≥ 100 篇，其中 Java 板块 ≥ 30 篇

## 常见越界案例（命中即判 No，直接停）

- [ ] 写 LeetCode 式判题 / 题库 → 阶段三 → **停**
- [ ] 拆微服务 / 给 gateway 加业务逻辑 → 阶段二之后 → **停**
- [ ] 接登录 / 支付 → 阶段二/三 → **停**
- [ ] 给 CodeRunner 加新语言 / 升级编辑器 → 上线前不做 → **停**
- [ ] 数据上云 / 用户系统 → 阶段二 → **停**

> 以上每一条都对应一个已经发生过或正在策划的越界。阶段一不缺功能，缺的是"上线"这一个动作。

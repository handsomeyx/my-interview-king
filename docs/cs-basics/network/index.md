# 计算机网络

> 面试必考。网络题核心三块：**分层模型、TCP（可靠传输）、HTTP/HTTPS（应用层）**。本文按问答组织，每题答 + 追问 + 易错点。

## 分层速览

| OSI 七层 | TCP/IP 四层 | 实际五层（教学） | 典型协议 |
|---|---|---|---|
| 应用 / 表示 / 会话 | 应用 | 应用 | HTTP / HTTPS / DNS / SMTP |
| 传输 | 传输 | 传输 | TCP / UDP |
| 网络 | 网络 | 网络 | IP / ICMP |
| 数据链路 | 网络接口 | 数据链路 | ARP |
| 物理 | | 物理 | 比特流 |

记忆顺序（上到下）：应用（HTTP）→ 传输（TCP）→ 网络（IP）→ 链路（ARP/MAC）→ 物理（比特）。口诀「应传网链物」。

## Q1：TCP 三次握手？为什么三次？

**答**：
1. 客户端 → 服务端：`SYN`（seq=x）。
2. 服务端 → 客户端：`SYN+ACK`（seq=y, ack=x+1）。
3. 客户端 → 服务端：`ACK`（ack=y+1）。

**为什么三次不是两次**：两次握手时，如果客户端的某个**旧 SYN 延迟到达**服务端（网络拥塞绕了一圈），服务端以为新连接请求，回 SYN+ACK 就分配资源建立连接——但客户端根本没打算连，资源白白浪费。三次握手让客户端有第三次确认的机会，服务端没收到第三次 ACK 就不真正分配资源。

**易错点**：三次的本质是「**双向**确认收发能力」——双方都要确认「对方能收我发的 + 我能收对方发的」。两次只确认了「服务端知道客户端能发」，没确认「客户端知道服务端能发」。

## Q2：TCP 四次挥手？TIME_WAIT 为什么？

**答**：
1. 主动方 → 被动方：`FIN`。
2. 被动方 → 主动方：`ACK`（被动方进入 `CLOSE_WAIT`，可能还有数据要发）。
3. 被动方 → 主动方：`FIN`（数据发完了）。
4. 主动方 → 被动方：`ACK`。主动方进入 `TIME_WAIT`，等 **2MSL** 后真正关闭。

**TIME_WAIT 为什么 2MSL**：
1. 保证最后的 ACK 能到对端（对端没收到会重发 FIN，主动方还能再发 ACK）。
2. 让旧连接的报文都消失（2MSL 后旧包在网络中自然过期，避免影响同四元组的新连接）。

**易错点**：TIME_WAIT 是**主动关闭方**进入（不是被动方）。服务端主动关闭会积累大量 TIME_WAIT（每条占一个本地端口），所以生产里服务端一般不主动关、让客户端关，避免端口耗尽。

## Q3：TCP 和 UDP 区别？

**答**：
| 维度 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接（握手） | 无连接 |
| 可靠性 | 可靠（重传/序号/流量控制/拥塞控制） | 不可靠（尽最大努力） |
| 有序性 | 有序（序号重组） | 无序 |
| 速度 | 慢 | 快 |
| 头开销 | 20 字节 | 8 字节 |
| 场景 | HTTP / SSH / 邮件 | DNS / 视频流 / 直播 / 游戏 |

**追问**：为什么视频用 UDP？→ 实时性 > 可靠性（丢一帧不重传，重传到了也早过时了），TCP 的重传反而卡顿。QUIC（HTTP/3 的传输层）就是基于 UDP 实现「类 TCP 可靠」+ 无队头阻塞。

## Q4：HTTPS 原理？SSL/TLS 握手？

**答**：HTTPS = HTTP + SSL/TLS，在 TCP 之上加密。握手（简化）：
1. Client Hello（带支持的加密套件 + 随机数 R1）。
2. Server Hello（选加密套件 + 随机数 R2 + 证书）。
3. 客户端验证证书（走 CA 签名链 → 信任根 CA）。
4. 客户端生成 pre-master secret，用证书公钥加密发给服务端。
5. 双方用 R1+R2+pre-master 算出会话密钥（对称）。
6. 后续通信用对称密钥加密。

**为什么用混合加密**：非对称（RSA）慢，只用来安全交换会话密钥；后续大量数据用对称加密（AES）快。

**易错点**：HTTPS 端口 **443**（HTTP 80）。证书防的是「**中间人冒充服务端**」——加密本身是「身份认证 + 协商密钥」的副产物，**身份认证才是 HTTPS 的核心目的**。没有证书的加密没意义（你加密给的就是中间人）。

## Q5：HTTP 1.0 / 1.1 / 2.0 / 3.0 区别？

**答**：
- **1.0**：每次请求新建 TCP 连接（短连接），开销大。
- **1.1**：`keep-alive` 长连接（复用 TCP）、管道化（但浏览器基本不用，有队头阻塞）、`Host` 头（支持虚拟主机）。
- **2.0**：二进制分帧、**多路复用**（一个 TCP 并发多个请求，解决 HTTP 层队头阻塞）、头部压缩（HPACK）、服务端推送。
- **3.0**：基于 **QUIC**（UDP），解决 TCP 层队头阻塞。

**易错点**：HTTP/2 解决了「**应用层**队头阻塞」（多请求并发），但底层 TCP 仍队头阻塞（一个包丢了，后面的包即使到了也要等重传）；HTTP/3 换成 UDP（QUIC 自己实现可靠）才彻底解决 TCP 队头阻塞。

## Q6：输入 URL 到页面显示全流程？

**答**（面试高频「串场题」，把各层串起来）：
1. **DNS 解析**：域名 → IP（浏览器缓存 → OS hosts → 本地 DNS → 递归查根/顶级/权威）。
2. **建立 TCP 连接**：三次握手。
3. **TLS 握手**（HTTPS）：协商加密套件 + 验证证书 + 协商会话密钥。
4. **发 HTTP 请求**：构造请求行/头/体。
5. **服务端处理 + 响应**：反向代理（Nginx）→ 应用（Spring Boot）→ 数据库。
6. **浏览器渲染**：解析 HTML → DOM、CSS → CSSOM、合成渲染树 → 布局（layout）→ 绘制（paint）→ 合成（composite）。
7. **断开连接**：四次挥手（或 keep-alive 复用）。

**易错点**：这题是「**串场题**」，面试官想看你对每层的理解。别只背流程，要在关键步展开（DNS 递归 vs 迭代、TCP 为什么三次、TLS 为什么对称+非对称、渲染的重排 vs 重绘）。背流程是及格，能展开是加分。

## 易错点速查表

| 知识点 | 关键 |
|---|---|
| 三次握手 | 第三次是 ACK（不带 SYN）；本质是双向收发确认 |
| 四次挥手 | TIME_WAIT 在**主动方**，等 2MSL；被动方先 CLOSE_WAIT 后 LAST_ACK |
| TIME_WAIT | 服务端主动关会积累 TIME_WAIT 占端口，让客户端关 |
| HTTP/2 vs HTTP/3 | HTTP/2 解决应用层队头阻塞；HTTP/3 换 UDP 解决 TCP 层 |
| HTTPS 端口 | 443（HTTP 80） |
| HTTPS 核心 | 身份认证（证书）为主，加密为辅 |
| DNS 递归 vs 迭代 | 客户端 ↔ 本地 DNS 递归；本地 DNS ↔ 根/顶级/权威 迭代 |
| ARP | IP → MAC（局域网内解析），跨网段靠网关转发 |

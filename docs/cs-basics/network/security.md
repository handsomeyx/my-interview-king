# Web 安全（XSS / CSRF / SQL 注入 / 点击劫持）

> 配套：[网络总览](./) + [TCP/HTTP 深入](./tcp-http)。本篇讲 Web 四大常见攻击 + 防御。

---

## Q1：XSS（跨站脚本）

**答**：攻击者把恶意 JS 注入网页，其他用户浏览时执行。三种：
- **反射型**：恶意脚本在 URL 参数，服务器取出拼到响应（如搜索框回显）。用户点恶意链接触发。
- **存储型**：恶意脚本存到数据库（如评论），所有访问者中招。**危害最大**。
- **DOM 型**：前端 JS 直接把用户输入插入 DOM（如 `innerHTML`），不经过服务器。

**防御**：**输出转义**（不是输入过滤）——数据渲染到 HTML 时转义 `< > & "`（用框架转义或 OWASP ESAPI）。富文本用**白名单**（jsoup whitelist）。`innerHTML` 改 `textContent`。CSP（Content-Security-Policy）限制脚本源。

**易错点**：XSS 防御是「**输出时**按上下文转义」（HTML body / 属性 / JS / URL 不同转义规则），**不是「输入时过滤」**——输入过滤会误伤合法内容（如用户名合法含 `<`），且不同输出点需不同转义。很多人在入库时过滤，结果换一个输出场景（如 JS 字符串）就漏。

## Q2：CSRF（跨站请求伪造）

**答**：攻击者诱导已登录站点 A 的用户访问恶意页面，恶意页面构造请求发给 A。浏览器自动带 A 的 Cookie，A 以为是用户自愿操作（转账 / 改密码）。

**XSS vs CSRF**（关键区别）：
- **XSS 是「偷」**：注入脚本偷数据 / 执行操作（攻击者在用户的浏览器里跑代码）。
- **CSRF 是「借」**：借用户的登录身份发请求（攻击者不在用户浏览器里，靠浏览器自动带 Cookie）。

**防御**：
1. **CSRF Token**：服务器发一次性 token，表单携带，服务器校验。攻击者构造的请求拿不到 token。
2. **SameSite Cookie**（现代浏览器默认 Lax）：`Set-Cookie: ...; SameSite=Strict/Lax`，跨站请求不带 Cookie。最省事。
3. **Referer 校验**：服务器检查请求来源（不靠谱，Referer 可被策略去掉）。

**易错点**：**GET 请求不该有副作用**（不该用 GET 转账/改数据）——CSRF 最容易构造 GET 请求（一个 `<img src=...>` 就发请求）。重要操作用 POST + Token。

## Q3：SQL 注入

**答**：用户输入拼到 SQL，攻击者构造输入改变 SQL 语义。如登录 `' OR '1'='1` → `SELECT * FROM user WHERE name='' OR '1'='1' --' AND pwd='xxx'`，永真绕过登录。

**防御**：**预编译**（PreparedStatement）——SQL 模板和参数分开传，参数只当数据不当 SQL 语法。MyBatis 用 `#{}`（预编译占位）**不用** `${}`（字符串拼接）。

**易错点**：预编译**只对值有效**，对「表名 / 列名 / 排序字段（ORDER BY）」**无效**——这些是 SQL 结构，不能用占位符。动态表名/排序要**白名单校验**（只允许预定义的列名），不能直接拼接用户输入。

## Q4：点击劫持（ClickJacking）

**答**：攻击者用透明 `<iframe>` 套住正常页面，诱导用户点看似无害的按钮，实际点到 iframe 里的敏感操作（如「删除账户」「授权」）。

**防御**：`X-Frame-Options: DENY / SAMEORIGIN`（禁止被 iframe 嵌入）或 CSP `frame-ancestors 'none'`。

**易错点**：`X-Frame-Options` 是**响应头**（服务器设），不是前端 JS。前端写的 `if (top !== self) top.location = self.location`（frame-buster）可被攻击者用 `sandbox` 属性绕过，不可靠。

## Q5：中间人攻击（MITM）

**答**：攻击者介于客户端和服务器之间，截获 / 篡改通信。

**防御**：**HTTPS**（TLS 加密 + 证书身份认证）。证书防的是「冒充服务端」——中间人没真私钥，无法完成握手；即使转发，加 密的内容也看不到。

**易错点**：HTTPS 防 MITM 的关键是**证书链 + 客户端校验**。如果用户点「忽略证书警告」继续访问（中间人用自签证书），HTTPS 也防不住——所以**别忽略证书警告**。

## 易错点速查表

| 攻击 | 防御 | 关键易错 |
|---|---|---|
| XSS | 输出转义（按上下文）| 防御是**输出时**转义，不是输入过滤 |
| CSRF | Token / SameSite / 重要操作 POST | GET 不该有副作用；SameSite 最省事 |
| SQL 注入 | 预编译（PreparedStatement / `#{}`）| 预编译对表名/列名无效，用白名单 |
| 点击劫持 | `X-Frame-Options` 响应头 | 是服务器响应头，不是前端 JS |
| MITM | HTTPS（证书 + 客户端校验）| 别忽略证书警告 |

# 安全工程

## 安全基础

### 安全概念
- **保密性**：确保信息不被未授权访问
- **完整性**：确保信息不被未授权修改
- **可用性**：确保系统和服务可用
- **认证**：验证用户身份
- **授权**：授予用户适当的权限
- **审计**：记录和审查系统活动

### 威胁模型
- **STRIDE**：欺骗、篡改、否认、信息泄露、拒绝服务、权限提升
- **DREAD**：损害、可复现性、可利用性、影响用户、可发现性
- **攻击树**：可视化攻击路径

### 安全原则
- **最小权限**：只授予必要的权限
- **防御纵深**：多层防御
- **最小暴露**：减少攻击面
- **安全默认**：默认安全配置
- **失败安全**：故障时保持安全状态
- **责任分离**：分离关键职责

## 身份认证

### 认证方法

#### 密码认证
- **密码策略**：复杂度要求、定期更换、密码长度
- **密码存储**：哈希存储、盐值、bcrypt/scrypt/Argon2
- **多因素认证**：结合多种认证因素

#### 生物认证
- **指纹识别**：指纹扫描
- **面部识别**：面部特征识别
- **虹膜识别**：虹膜特征识别
- **声纹识别**：声音特征识别

#### 令牌认证
- **API 密钥**：简单的 API 访问凭证
- **OAuth 2.0**：授权框架
- **OpenID Connect**：基于 OAuth 2.0 的身份层
- **JWT**：JSON Web Token

### 认证流程

#### 单点登录 (SSO)
- **定义**：一次登录访问多个系统
- **协议**：SAML、OAuth 2.0、OpenID Connect
- **优势**：简化用户体验、集中认证管理

#### 多因素认证 (MFA)
- **定义**：使用多种认证因素
- **因素类型**：知识因素、 possession 因素、 inherence 因素
- **实现**：短信验证码、身份验证器应用、硬件令牌

## 授权

### 授权模型

#### 基于角色的访问控制 (RBAC)
- **概念**：基于用户角色分配权限
- **组成**：用户、角色、权限、资源
- **优势**：易于管理、可扩展性好

#### 基于属性的访问控制 (ABAC)
- **概念**：基于属性的访问控制
- **属性**：用户属性、资源属性、环境属性
- **优势**：更灵活、细粒度控制

#### 基于策略的访问控制 (PBAC)
- **概念**：基于策略的访问控制
- **策略**：基于规则的策略
- **优势**：更灵活、可动态调整

### 权限管理
- **权限设计**：细粒度的权限设计
- **权限分配**：合理分配权限

## 应用安全

### 安全编码

#### 常见漏洞
- **注入**：SQL 注入、NoSQL 注入、命令注入
- **跨站脚本 (XSS)**：存储型、反射型、DOM 型
- **跨站请求伪造 (CSRF)**：利用用户身份执行未授权操作
- **不安全的直接对象引用**：直接访问敏感资源
- **安全配置错误**：错误的安全配置
- **敏感数据暴露**：未保护的敏感数据
- **缺少功能级访问控制**：未验证功能级权限
- **跨域资源共享 (CORS) 配置错误**：不安全的 CORS 配置
- **使用含有已知漏洞的组件**：使用过时或有漏洞的组件
- **日志记录和监控不足**：缺少日志记录和监控

#### 安全编码实践
- **输入验证**：验证所有输入
- **输出编码**：编码输出以防止 XSS
- **参数化查询**：防止 SQL 注入
- **最小权限**：使用最小必要权限
- **安全库**：使用安全的库和框架
- **代码审查**：定期进行代码审查
- **自动化扫描**：使用自动化安全扫描工具

### 安全测试

#### 渗透测试
- **黑盒测试**：无源码访问
- **白盒测试**：有源码访问
- **灰盒测试**：部分源码访问
- **社会工程学测试**：测试人员安全意识

#### 漏洞扫描
- **静态应用安全测试 (SAST)**：静态分析代码

# Agent底层底座

## 思考锚点

LLM 是 AI Agent 的「大脑」，但这个大脑不是天生就会工作的——它需要架构设计（Transformer）来思考、需要 Prompt 来指挥、需要训练数据来优化、需要 RAG 来补充实时知识。

理解 LLM 的关键是理解它的「能力边界」：LLM 擅长理解和生成自然语言，但不擅长精确计算、不具备实时知识、容易产生幻觉。这些局限性不是 LLM 的缺陷，而是它的设计 trade-off——为了通用的语言理解能力，牺牲了精确性和时效性。

所以 Agent 的工程实践都是围绕「弥补 LLM 的短板」展开的：用 RAG 补充实时知识、用工具调用解决精确计算、用 Prompt 工程减少幻觉、用微调对齐特定领域。

在上一部分的前置知识中，我们已经知道，LLM（大型语言模型）是 AI Agent 的"超级大脑"——Agent 能自主思考、理解需求、完成任务，核心都依赖 LLM 的支撑。

这一部分我们主要系统的拆解LLM的核心技术：
-**模型架构**：“大脑”的构造。
- **Prompt**：如何指挥大脑。
- **微调训练**：优化大脑。
- **RAG** ：给大脑补充知识。
- **LLM运维**：保障大脑稳定工作。

## 模型架构
决定模型的思考能力、反应速度和增长领域。

### Transformer架构

目前所有主流的LLM，本质上都是基于Transformer架构构建的。你只需要记住它的核心作用和基本结构：
- **核心作用**：让模型能“理解上下文” ，捕捉语言规律。比如说我喜欢喝美式，它的口感很苦”，Transformer 能理解“它”指的是“美式咖啡”。
-**基本架构**：**Encoder（编码器）**，把文字转换成模型能识别的语言（向量），同时捕捉文字间的关系。**Decoder（解码器）**，根据编码器理解的内容，一步步生成符合逻辑，符合人类语言习惯的回答。

Transformer 架构的核心是“**注意力机制**”，简单说就是“让模型学会关注重点”——比如你问“如何做一杯美式咖啡”，模型会重点关注“美式咖啡”“做法”这些关键词，而不是无关的内容，这也是它比传统模型更智能的核心原因。

###  模型缩放

LLM之所以能回答出一些我们的问题，是因为在创造它之前，我们就对它进行了训练。那这里发起一个疑问，模型的规模越大，性能就一定越好吗？ 答案是：**在一定范围内，是的**。
- **核心规律**：模型的参数越多，训练数据越丰富——模型的理解能力、推理能力、生成能力就越强——能理解更复杂的需求，生成更连贯的内容
- 当然也不是越大越好，在一定规模后，性能会提升变慢，反而增加模型的**训练成本**，**部署成本**比如需要更多的服务器资源。

### 模型的变体

基于 Transformer 架构，工程师们开发出了不同类型的 LLM 变体，它们就像“不同性格的人”，各有擅长的领域，适合不同的 Agent 场景。

- **编码器-解码器架构（Encoder-Decoder）**：擅长“**翻译、摘要、问答**”——比如 T5 模型，适合做客服 Agent 的问答功能、文档摘要功能；
- **解码器架构（Decoder-Only）**：擅长“**生成类任务**”——比如 GPT 系列、LLaMA 系列，适合做 Agent 的对话、代码生成、任务规划功能（AI Agent 最常用的模型类型）；
- **多模态变体**：能理解图片、语音、视频等多类型信息——比如 **GPT-4V、文心一言多模态版**，适合做多模态 Agent（比如能识别图片的旅行规划 Agent）

### 扩展内容：
#### 1.自注意力机制
Transformer完全基于自注意力机制（Self-Attention） 的深度学习模型，可以并行。自注意力你可以认为就是给不同的词分配权重，重点关注相关的词。

传统的RNN/CNN机制：
- **RNN**：按序列逐个处理数据
- **CNN**：局部窗口提取特征，只看附近几个字的关系。

#### 2.Encoder 和Decoder的机制
Encoder基于双向注意力机制，适合理解类任务（BERT），双向注意力允许你能看到上下文的所有位置，从而注意权重，适合**理解类的任务**，就是看懂意思。

Decoder基于单向掩码注意力+编码器注意力，适合**生成类任务**。掩码单向注意力，防止训练时看到未来的Token，避免信息泄漏；编码器注意力；解码器去关联编码器上下文的内容，回头看原文。所以说都适合基于原先的内容取生成。

#### 3.LLM的核心组件：
- **位置编码（Positional Encoding）**：模型本身不天然感知时序结构，所以我们必须加入位置信息，让模型知道词的顺序。区别**相对位置编码**和**RoPE**：相对位置编码我只关注**距离差**。RoPE方法把向量看成复数，通过**旋转**来编码位置。
- **多头注意力（Multi-Head Attention）**：把 线性层投影出多个Q/K/V 子集，从不同子空间学习不同类型的依赖关系，比单头表达能力更强。Q 来自解码器，K/V 来自编码器输出。你只需要知道它的核心是**并行捕捉不同类型的依赖关系**，也就是**从不同角度提取特征**。
- **前馈网络（FFN）**：它的作用就是对每个Token独立做特征变换或升维降维，**让模型能学习复杂、弯曲的非线性的特征关系**。**升维降维**：把隐藏维放大（比如 768 → 3072），用高维空间做非线性变换，再降维回原维度。**特征变换**：比如原先[x,y]的平面坐标，经过选择+平移—[x',y']。
- **残差训练+层归一化**：残差训练让梯度直接跳过层传播，保证深层可训练，网络层做变换后，原始输入直接加进去，哪怕这层学习得很差，至少保留了原始信息、层归一化稳定训练，是对每个样本独立归一化，区别于 BatchNorm，且能缓解内部协变量偏移。

#### 4.温度和top-p
-**温度**：控制大模型输出的**随机性**，**创造性**。取值一般在**0-2**。数值越小，输出越稳定。
-**top-p**：核采样，控制模型只从**概率累积和到p的最小词汇集合选词**，越小，可选越少，输出越保守。

#### 5.描述Transformer Decoder的完整解码流程
首先对已经生成的序列做词嵌入与位置编码，经过掩码自注意力，保证只看到前文，再通过交叉注意力关注编码器输出的上下文信息，接着经过前馈网络，残差和归一化训练，多层的block堆叠后，通过线性层与Softmax输出下一个token的概率分布，最后不断迭代生成，知道结束输出。

-**Softmax**：把一组任意数字-变成总和为1的概率分布

## Prompt工程：如何指挥LLM更高效的工作
Prompt工程，对LLm来说，就是设计更有效的指令，让LLM更快、更准确的理解你的需求，输出你的结果。
### Prompt设计

如何设计有效的Prompt呢，这里给出三个核心原则：
-**明确需求**：告诉LLM做什么、怎么做、输出什么格式。
-**给出示例**：如果需求比较复杂，可以给LLM一个示例
-**限定范围**：避免LLM输出无关内容，明确输出的范围、语气、格式。

### Prompt优化

有时候你设计的Prompt可能得不到理想的结果，这时候就需要优化Prompt：
- **增加细节**：补充更多需求的细节，让LLM更清楚你的意图
- **调整语气**：对LLM进行角色设定，让他以特定的身份输出
- **拆分复杂任务**：如果任务比较复杂，把他拆分成多个小人物，分步骤让LLM完成

### Few-shot Learning
**少样本学习**，简单来说就是给LLM几个实例，让它快速学会新技能。给 LLM 几个示例，让它快速学会新技能”——比如你想让 LLM 识别“用户的情绪是开心还是生气”，不用给它海量的数据训练，只需给它3-5个示例，它就能快速掌握识别方法。

**示例**：想让 LLM 识别用户情绪，Prompt 可以这样设计：“请识别用户的情绪（开心/生气），示例1：用户说‘太开心了，订单很快就到了’→ 开心；示例2：用户说‘怎么还没发货，太离谱了’→ 生气；用户说‘这个功能太好用了，点赞’→ ？”，LLM 就能根据示例，快速输出“开心”。

## 微调与训练

我们前面说的LLM都是“通用型模型”——它们能处理各种通用需求，但在特定的Agent的场景，比如金融，医疗，代码，可能表现不够好，这时候，需要对LLM进行微调与训练，让他更适配具体的场景。

### 微调的方法：
只需要重点理解3个微调方法：
- **LoRA微调**：不用修改模型的全部参数，只修改部分参数，训练速度快，成本低。显存省下70%
- **Adapter**：方法是在Transform层插入小的 神经网络模块，训练时固定主干，只调这些小模块
- **全参数微调**：修改模型的所有参数，微调效果最好。适合数据质量高，预算充足的场景

### 数据集准备
- **数据集类型要对准**：要选择与Agent场景相关的数据
- **数据质量**：数据要准确、规范、避免错误数据，否则会让模型学坏。
- **数据量**：不用追求海量数据，少样本微调就能满足大部分的Agent场景

### 训练技巧
- **控制训练步数**：训练步数不是越多越好，步数太多会导致模型“过拟合”（比如只会记住训练数据，不会处理新的需求），步数太少则会导致“欠拟合”（模型没学会场景规律），一般根据数据集大小，调整到合适的步数即可；
- **调整学习率**：学习率是“模型学习的速度”，太大容易导致模型训练不稳定，太小则训练速度太慢，新手可以参考行业最佳实践，选择合适的学习率（比如 LoRA 微调，学习率一般设置为1e-4）
- **验证数据集**：准备一部分“验证数据”，训练过程中不断用验证数据测试模型效果，一旦发现模型效果不再提升，就停止训练，避免过拟合。

### 常见的后训练方法和优缺点：
**后训练**，指在模型完成 ** 预训练（Pre-training）** 之后，对模型参数进一步优化的一系列训练方式的统称。目标是让模型更懂领域、更听话、更安全，更对齐人类。

接下来介绍常见的**后训练方法**：
-**FFT全参数微调**：把大模型全部权重拿出来，用下游数据重新训练。极其耗显存、耗时间、成本高，而且容易**过拟合、灾难性遗忘**。
-** PEFT**：冻结原模型，只训练少量低秩小矩阵。常见的方法是**LoRA**，不修改预训练模型的原始权重，只在 Transformer 注意力层的权重矩阵旁，插入两个低秩矩阵来学习任务特定的知识。大幅减少参数量，**降低训练成本**，利用低秩的本质，**避免过拟合**。
-**PT，提示Tuning**：只训练少量软提示 token，模型权重完全冻结。**超省资源，几乎不占显存，但是能力改造最弱。**
-**SFT监督微调**：用人工标注的 <输入，输出> 对去微调模型，让模型对齐人类意图，听话、格式规范，所以依赖高质量的标注数据。
-**DPO 直接偏好优化 **：不用奖励模型，直接用 ** 对比数据（好回答 vs 坏回答）** 训练。对齐效果强，回答更安全、更贴合偏好，但是需要偏好数据。
-**RLHF基于人类反馈的强化学习 **：奖励模型 + PPO 强化学习。首先人工给回答打分-训练奖励模型RM，用RM给模型输出打分，PPO调整模型，让高分回答概率变高。对齐效果最强，回答质量最高。

补充：
-**过拟合**：模型在训练集上表现极好（误差极低），但在未见过的测试集 / 真实数据上表现极差的现象。
- **低秩**：秩代表数据的「有效信息维度」，低秩的意义在于高维数据中真正有用的信息远少于维度本身，可通过低秩分解。
- **灾难性遗忘**：神经网络在学习新任务 / 新数据时，原有已掌握的知识、能力被快速、大幅、不可逆地破坏的现象。
- **奖励模型**：是一个专门对大模型输出进行优劣打分的模型。
- **正则化**：正则化是机器学习中抑制模型**过拟合**、提升泛化能力的一类技术的统称，本质在损失函数中加入额外的惩罚项，限制模型参数的复杂度，防止模型过度学习训练数据中的噪声和冗余特征。

## RAG技术
我们前置知识中提到，LLM它会说胡话，而且知识是固定的。而**RAG**技术就能完美解决这个问题——RAG简单说就是给LLM配一个专属知识库，让它回答问题，先从知识库中检索相关信息，再生产回答。

对于 AI Agent 来说，RAG 是核心技术之一——比如客服 Agent，需要根据企业的产品知识、售后规则回答用户问题，这就需要用 RAG 技术，把企业的专属知识“注入”到 LLM 中，让 Agent 能准确回答问题，避免幻觉。

### RAG原理
- **构建知识库**：把Agent所需的专属知识（比如产品手册，售后规则），整理成文档，存入检索数据库（比如**向量数据库**）。
- **检索相关信息**：当用户提出问题（比如“你们的产品保修多久”），Agent 会先把问题转换成“检索关键词”，从知识库中检索出与问题相关的内容（比如“产品保修期限为1年，人为损坏不保修”）。
- **生成回答**：3. 生成回答：LLM 结合检索到的信息，生成准确、规范的回答，避免输出错误内容（比如不会说“保修3年”，因为知识库中明确是1年）。

### 检索策略
如何从知识库中快速、准确地找到与问题相关的信息，常见的有两种：
- **向量检索（最常用）**：把问题和知识库中的文档，都转换成“**向量**”（模型能识别的数字），通过计算向量之间的相似度，找到最相关的文档——比如用户问“保修多久”，向量检索会快速找到包含“保修期限”的文档；
- **关键词检索**：通过提取问题中的**关键词**（比如“保修”“期限”），从知识库中匹配包含这些关键词的文档，适合知识库规模较小、文档结构简单的场景。

### RAG优化
目的是为了让检索更精准、回答更流畅。让Agent的回答更精准
- **优化知识库结构**：把知识库中的文档拆分成“小块”（比如每段文字拆成一个小文档），这样检索时能更精准地找到相关内容，避免检索到无关信息；
- **关键词优化**：对用户的问题进行“关键词提取”和“同义词替换”（比如用户说“质保多久”，替换成“保修期限”），让检索更全面；
- **多轮检索**：如果一次检索找不到相关信息，让 Agent 进一步追问用户（比如“请问你问的是哪款产品的保修期限？”），获取更多信息后，再进行二次检索，提升准确率。

## LLM运维
对于 Agent 工程师来说，LLM 运维是“工程落地”的核心能力，重点掌握“部署、监控、优化”三个方面即可。

### 让LLM能被Agent调用
将LLM放到服务器上，让Agent能通过API调用它，常见的有两种部署方式：

- **云服务部署**：直接使用各大厂商的 LLM 云服务（比如 OpenAI 的 API、百度文心一言的 API），不用自己搭建服务器，只需调用 API 就能让 Agent 使用 LLM，适合个人和中小企业；
- **本地部署**：把开源 LLM（比如 LLaMA、Qwen）部署到自己的服务器上，优点是“数据隐私性高”（不用把用户数据传到第三方云服务），适合对数据隐私有要求的场景（比如医疗、金融 Agent）

注意：部署时要注意资源匹配——比如大型LLMGPT-4这样的需要高端GPU，小型的LLM可以部署普通的服务器，避免资源浪费。

### 监控和服务

LLM被部署后，我们需要持续监控，及时发现问题，解决问题，重点关注3个核心指标：

- **响应速度**：监控 LLM 的响应时间（比如调用一次 LLM 需要多久），如果响应太慢，会影响 Agent 的用户体验（比如用户等待太久），需要优化；
- **输出质量**：监控 LLM 的输出内容，是否有幻觉、错误信息，如果有，需要优化 Prompt、补充 RAG 知识库，或者重新微调模型；
- **系统稳定性**：监控 LLM 服务是否会崩溃、是否会出现调用失败的情况，一旦出现，需要及时重启服务、排查问题（比如服务器资源不足）。

### 性能优化

LLM运行需要消耗大量的服务器资源，我们可以通过**性能优化**来提升Agent的响应速度，还能降低成本。
- **模型量化**：把 LLM 的参数“压缩”（比如从16位精度压缩到8位精度），减少内存占用和 GPU 消耗，同时尽量不影响模型性能——比如 Qwen-7B 量化后，能在普通 GPU 上流畅运行；
- **缓存优化**：把 LLM 常见的输出结果（比如用户常问的问题、固定的回复）缓存起来，下次 Agent 调用时，直接返回缓存结果，不用重新调用 LLM，提升响应速度、减少资源消耗；
- **并发控制**：限制同时调用 LLM 的请求数量，避免服务器资源被耗尽（比如设置每秒最多调用100次 LLM），确保系统稳定运行。

## LangChain

LangChain是面向LLM的开源开发框架，它把LLM、外部数据、工具等能力模块化、组合化，核心能力是**链式调用**，可以把多个步骤串起来。

**六大核心组件**：
-** Model IO**：和大模型对话的标准通道。
-**Date Connection**：让LLM用上外部私有/实时数据。
-**Memory **：让AI记住之前聊过什么。
-**Chains**：封装固定工作流，复用逻辑。
-**Agents**：让AI像人一样自主解决复杂问题。
-**Tools**：给LLm装上手脚，能操作外部世界。

### LangGraph
基于LangChain构建的有状态的多智能协作框架，把多个AIAgent交互过程建模成图，适合做需要**反复来回交互**的任务。

答：SFT 数据太窄、太单一，模型过度拟合领域数据，把预训练学到的通用知识 / 通用能力覆盖掉了。有以下几种解决办法：

- 不要只训练业务数据，混入10%~50%的通用对话/通用知识数据，一遍学领域知识，一遍苗定通用能力，不让模型跑偏。
- 降低学习率+减少训练次数。SFT不是越大越好，过猛训练一定会冲掉通用的能力，学习率调小：`1e-5 → 3e-6 ~ 1e-6`，减少 epoch，一般 1~3 轮足够。
- 使用高效微调，不要全量微调，全量微调更容易遗忘，LoRA 更不容易遗忘。
- 使用正则化，约束模型不要偏离原模型，训练时加约束，让新权重不要离预训练权重太远。 KL 散度约束，让 SFT 模型靠近原模型
</details>

2.DPO训练中模型输出变长是什么原因？如何解决？

<details>
<summary>点击查看答案</summary>
答：训练的话RM普遍给更长的回答更高分，长度差异他容易放大奖励信息了，所以可能就会出现变长=高分的捷径，在训练时候，容易放大变长问题。解决方案如下：

- 平衡长度分布，人工生成等长但质量不同的问题-回答对，强制模型学质量而非长度。
- 修正标注偏置，标注时明确要求：优先质量，长度仅作次要参考

</details>

4.KL散度的数学意义是什么?在模型对齐(如PPO/DPO)中起什么作用?
<details>
<summary>点击查看答案</summary>
答：KL散度也叫相对熵，用来衡量两个概率分布 P 和 Q 之间的差异程度。KL 散度就是衡量两个概率分布 “像不像” 的数值，越大越不像。

在 PPO 里的作用，用 KL 散度限制策略更新幅度，不让新策略更新得离旧策略太远，避免训练崩坏、灾难性遗忘。

在 DPO 里的作用，通过 KL 散度做正则化，让精调模型在学习人类偏好的同时，不与原参考模型偏离过大，避免灾难性遗忘，保证生成质量稳定

</details>

5.面对模型在生成过程中出现循环、重复回答的问题，有哪些解决办法?
<details>
<summary>点击查看答案</summary>
答：
先要清楚原因
- 数据里大量重复文本，SFT/DPO重复样本被标成高分。
- 注意力机制缺陷：前文的token权重过高，看自己刚生成的词，概率被进一步拉近
- 微调效果差：LoRA秩太低，训练不重复，SFT数据单一，DPO训练偏好保守

然后从五个维度回答：五个维度：生成参数，算法策略，工程约束，模型优化，后训练策略。

生成参数，合理设置top-p和温度。

算法策略：

- 重复检测和截断：实时检测连续重复片段，出现连续重复 >2 次直接停止生成。
- early stopping+长度限制：设置最大生成长度 max_new_tokens，强制停止，避免无限循环。

工程约束：
- Prompt明确禁止重复：“不要重复、不要循环、简洁回答、不要啰嗦”
- 强制结构化输出：让模型按固定格式输出：JSON、分点、步骤

模型优化：
- 推理链状态监控：记录历史思考步骤，检测是否在原地打转，连续 2 步相似 → 强制退出、给出结论。
- 外部校验+终止条件：连续 2 步相似 → 强制退出、给出结论。

后训练策略：
- SFT 高质量数据
- DPO/PPO 对齐，用 “不重复回答” 作为优胜样本，用 “重复循环回答” 作为劣样本。
</details>

6.啥是正则？L1正则和L2正则的区别是什么？从数学角度解释为什么L1能产生稀疏性？为什么深度学习里几乎都用 L2，很少用 L1
<details>
<summary>点击查看答案</summary>
答：在损失函数里加一项 “惩罚项”，限制模型权重不要太大、不要太复杂，防止过拟合。总损失=原损失+正则项。

L1正则：公式是原损失+正则项绝对值的和。通常用来进行特征选择，权重的结果很稀疏，有很多0。L2正则：公式是原损失+正则项的平方和，通常可以用来做权重衰减和防过拟合，很小但非0，对异常点敏感。

为什么 L1 能产生稀疏性？

L1 的约束区域是菱形，最优解容易落在坐标轴上导致权重为 0；且 L1 的梯度是固定大小的 ±1，会持续把权重推向 0，因此产生稀疏性。L2 是圆形约束，梯度随权重减小而减小，不会压到 0。

为什么深度学习里几乎都用 L2，很少用 L1？

L2 训练更稳定、好优化，正则项是 光滑可导 的，梯度处处连续，用反向传播非常稳定，深度学习模型大、层数多，稳定第一，所以优先 L2。L1 容易导致梯度消失 / 不稳定

</details>

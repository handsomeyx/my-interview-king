# 技能（Skill）能力

技能体系，就是 Agent 运用这些基础能力，真正落地解决实际问题的“核心本领”——就像人拥有“说话、思考、动手”等技能一样，Agent 的技能决定了它能完成哪些任务、完成得好不好。

本部分将严格按照既定框架，从工具调用、规划能力、记忆能力、推理能力到领域技能，由浅到深逐步解析，衔接前文知识，让你清楚每种技能的核心作用、实现方法，以及如何协同运用这些技能，为后续 Agent 工程实战和技能落地打下坚实基础。

## 一、AI Agent 核心技能
###  工具调用：
在上一部分 Agent 组件的学习中，我们简单了解过工具使用组件，而工具调用技能，就是“工具使用组件的核心能力”——它让 Agent 能跳出“文字生成”的局限，通过调用外部工具、API、插件，真正动手完成实际任务（比如查天气、发邮件、写代码、分析数据）.
1.1 **工具使用**

工具使用的核心，是“识别需求→选择工具→调用工具→获取结果”的闭环，Agent 首先要具备“判断什么时候用工具、用什么工具”的能力，再掌握工具调用的基本逻辑。

- **需求识别**：Agent 结合 LLM 的推理能力，判断当前任务是否需要调用工具——比如用户需求“帮我查明天北京的天气”，Agent 识别出“自己无法直接获取实时天气”，需要调用天气工具；

- **工具选择**：根据任务需求，选择合适的工具——比如查天气选择“天气 API 工具”，写代码选择“Python 解释器工具”，避免“用错工具”（比如用文本生成工具查天气）；

- **工具调用与结果处理**：按照工具的调用规范，传递正确的参数（比如查天气需要传递“城市、日期”），调用工具后，接收工具返回的结果，再结合 LLM 整理成用户能理解的内容。

案例：Agent 调用天气工具完成用户需求的过程：
      用户输入“帮我查明天北京的天气”；Agent 识别需求：需要实时天气数据，自身无法提供，需调用天气工具；选择工具：天气 API 工具，传递参数“城市：北京，日期：明天”；工具返回结果：“明天北京晴，气温10-20℃，微风”；Agent 整理结果，反馈给用户。

1.2 **Agent 如何“对接外部服务**

**API（应用程序接口）**是外部服务（比如天气服务、邮件服务、支付服务）提供的“调用入口”，API 集成技能，就是“让 Agent 能对接这些外部 API，实现更丰富的功能”——比如 Agent 集成邮件 API 就能发送邮件，集成支付 API 就能完成支付，是工具调用技能的核心延伸。

API 集成的核心是“遵循 API 规范”——不同的外部服务，API 调用格式、参数要求不同，Agent 需要按照对应服务的规范进行集成，同时结合 MCP 协议，将 API 调用结果封装成规范格式，更新到上下文。

1.3 **Agent 如何“扩展自身能力**

插件是“**可复用的工具模块**”，比如“图片识别插件”“语音转换插件”，插件开发技能，就是“开发适合 Agent 的插件，扩展 Agent 的能力范围”——当现有工具无法满足需求时，通过开发插件，让 Agent 具备新的技能（比如开发“PDF 解析插件”，让 Agent 能解析 PDF 内容）。

- **插件轻量化**：避免插件功能过于复杂，专注于单一功能（比如只做 PDF 解析，不兼顾图片识别），提升调用效率；
- **兼容性**：确保插件能适配主流 Agent 框架和 MCP 协议，方便后续复用和扩展；
- **可测试**：开发完成后，对插件进行测试，确保调用稳定、结果准确。

**规划能力**：

规划能力，是 Agent **自主**完成复杂任务的核心——它让 Agent 能“理清思路、明确步骤、合理分配资源”，就像人做事情前会“制定计划”一样，Agent 通过规划能力，将复杂任务拆解成可执行的小步骤，有序推进，避免混乱。

### 2.1 任务规划：

任务规划的核心，是“将复杂任务拆解成可执行的子任务，明确子任务的优先级和执行顺序”，核心依赖 LLM 的推理能力和上下文管理，小白重点掌握2个核心步骤：

- **任务拆解**：将复杂任务拆解成多个简单、可执行的子任务——比如用户需求“帮我完成周报并发送给领导”，拆解成“写周报→检查周报→发送邮件”3个子任务；

- **优先级排序**：根据子任务的依赖关系和紧急程度，排序执行顺序——比如“写周报”是前提，必须先执行，“检查周报”在“写周报”之后，“发送邮件”在最后。

### 2.2 路径规划

路径规划，是“在多个可执行路径中，选择最优路径”——比如 Agent 完成任务有多种方法，路径规划能力让 Agent 能判断“哪种方法最高效、最节省资源”，避免走弯路。

- **基础路径规划算法**：比如贪心算法（优先选择当前最优的步骤）、动态规划算法（考虑整体最优），小白不用深入掌握算法细节，只需了解“Agent 会通过算法选择最优路径”；

- **实际应用**：比如 Agent 查天气，有“调用天气 API”和“查询本地天气缓存”两种路径，路径规划能力会让 Agent 选择“查询缓存”（更快速、节省资源），若缓存无数据，再调用 API。

### 2.3 资源规划

路径规划完后，要开始进行资源规划，我们要合理分配 Agent 可调用的资源（比如时间、算力、工具），确保任务高效完成，避免资源浪费——比如 Agent 同时处理多个任务，需要合理分配算力，避免某个任务占用过多资源，导致其他任务延迟。

- **资源识别**：明确 Agent 可调用的资源（比如算力、工具、时间）；
- **资源分配**：根据任务的优先级和资源需求，分配资源——比如高优先级任务（比如紧急客服咨询）分配更多算力，低优先级任务（比如日志整理）分配较少算力；
- **资源优化**：实时监控资源使用情况，调整资源分配，避免资源浪费——比如某个任务完成后，释放占用的算力，分配给其他任务。

## 记忆能力

在上一部分上下文管理的学习中，我们了解过上下文的存储和更新，而记忆能力，就是“上下文管理的核心延伸”——它让 Agent 能“记住”短期交互信息、长期用户偏好和历史经验，实现连贯交互和自主优化，是 Agent 体现“智能性”的关键技能。

### 3.1 短期记忆

短期记忆，是 Agent 存储“当前交互会话的临时信息”的能力，核心特点是“临时存储、任务结束后可清理”，主要用于支撑当前任务的连贯执行。

- **核心机制**：短期记忆主要存储在内存中，读取速度快，能快速调用——比如当前会话中，用户说“帮我查明天北京的天气”，Agent 短期记忆会存储“用户需求、查询结果”，当用户追问“后天呢”，Agent 能快速从短期记忆中获取之前的交互信息，不用用户重复说明；

- **存储内容**：当前用户需求、任务执行步骤、工具调用结果、临时参数等；

- **管理方法**：任务结束后，及时清理短期记忆，避免占用过多内存——比如用户结束天气查询会话后，清理该会话的短期记忆，只保留长期有用的信息（比如用户喜欢查询北京的天气）。

### 3.2 长期记忆：Agent 的“长期记忆”

长期记忆，是 Agent 存储“长期有用信息”的能力，核心特点是“长期保留、可检索、可更新”，主要用于适配用户偏好、优化自身行为。

- **存储内容**：用户偏好（比如喜欢喝美式咖啡、不喜欢辣的食物）、历史任务经验（比如之前规划旅行的偏好、调用工具的成功案例）、领域知识（比如代码生成的常用模板）；
- **存储方法**：长期记忆通常存储在**向量数据库**（比如 Pinecone、Milvus）中，结合 RAG 技术，方便快速检索——比如用户让 Agent 写代码，Agent 从长期记忆中检索常用代码模板，快速生成代码；
- **记忆更新**：定期更新长期记忆，删除过期信息、新增有用信息——比如用户的偏好发生变化，Agent 及时更新长期记忆中的相关内容。

### 3.3 记忆优化

如果记忆信息过多、过于杂乱，会导致 Agent 检索缓慢、记忆混淆，影响交互效率——记忆优化，就是“精简记忆内容、提升检索效率”，我们需要掌握3个核心方法：

- **记忆压缩**：将冗长的记忆信息进行压缩，保留核心内容——比如将“用户说‘我想查明天北京的天气，因为我要去北京出差，需要准备薄外套’”压缩为“用户：查明天北京天气（出差，需薄外套）”；

- **记忆索引**：为长期记忆添加关键词索引（比如“北京、天气、出差”），让 Agent 能快速检索到相关记忆——比如用户问“北京出差天气”，Agent 能通过关键词快速找到之前的记忆；

- **记忆清理**：定期清理长期记忆中的过期信息（比如用户不再关注的偏好、过时的领域知识），避免占用过多存储资源，提升检索效率。

## 推理能力

推理能力，是 Agent 的“核心思考能力”——它让 Agent 能“理解用户需求、分析问题、判断下一步行动”，核心依赖 LLM 的推理能力，是 Agent 自主决策的关键，贯穿所有技能的运用过程。

### 4.1 逻辑推理：Agent 的“逻辑思维”

逻辑推理，是 Agent “按照逻辑规则分析问题、得出结论”的能力——比如 Agent 能通过逻辑推理，分析用户需求的核心、判断任务的可行性，避免出现逻辑错误。

- **核心实现方法**：基于 LLM 的 Chain-of-Thought（思维链）技术，引导 LLM 逐步推理——比如用户问“100减去25再加30等于多少”，Agent 会通过逻辑推理“100-25=75，75+30=105”，得出结论。

### 4.2 常识推理

常识推理，是 Agent “基于日常生活常识、领域常识，分析问题、得出结论”的能力——比如 Agent 知道“夏天天气热，需要穿薄衣服”“下雨需要带伞”，能结合常识，理解用户的潜在需求。

- **核心知识获取**：常识推理依赖 LLM 训练过程中学习到的常识知识，以及 Agent 长期记忆中存储的常识内容——比如 Agent 从长期记忆中获取“北京夏天炎热”的常识，当用户问“夏天去北京需要带什么”，Agent 能给出“带薄衣服、防晒霜”的建议；


### 4.3 因果推理

因果推理，是 Agent “分析事件之间的因果关系，判断‘为什么会发生’‘会导致什么结果’”的能力——比如 Agent 能分析“工具调用失败的原因”，并给出解决方案，是 Agent 自主优化的核心能力。

- **错误分析**：比如 Agent 调用天气 API 失败，通过因果推理，分析“失败原因是参数错误（未传递城市编码）”，并调整参数重新调用；

- **结果预测**：比如用户问“明天去户外野餐，下雨了怎么办”，Agent 通过因果推理，预测“下雨会导致野餐无法进行”，并给出“改期、找室内场地”的建议。

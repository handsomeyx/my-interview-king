# Java基础面试的考点
这一部分我只罗列我面试中遇到的面试知识点，不一定全，大家在面试中遇到没见过的可以自行补充。同时，我求方便，这一章节也包含了JVM和JUC的内容。

## 核心关键字
1. **final**：核心考察3个用法——修饰类（不可被继承）、修饰方法（不可被重写）、修饰变量（基本类型值不可改，引用类型地址不可改，对象内容可改），补充：修饰方法参数时，参数在方法内不可重新赋值。
2. **static**：比如“static修饰的方法和普通方法的区别”。核心是“属于类，不属于实例”，可直接通过类名调用，所有实例共享静态变量；静态代码块在类加载时执行一次，用于初始化静态资源，静态内部类不依赖外部类实例。
3. **this与super**：常问“二者区别”。this指代当前对象，用于访问当前对象的属性、方法和构造器；super指代父类对象，用于访问父类的属性、方法和构造器，核心是区分“当前实例”和“父类实例”的调用场景。

## 字符串相关
1. **String、StringBuilder、StringBuffer的区别**：核心是“可变性”和“线程安全”。String不可变，每次修改都会创建新对象，性能最低；StringBuffer线程安全（方法加synchronized），性能中等；StringBuilder非线程安全，性能最高，区分单线程/多线程使用场景即可。
2. **“==”与equals()的区别**：几乎所有大厂一面都会问。“==”比较基本类型是比“值”，比较引用类型是比“内存地址”；equals()是Object类的方法，默认和“==”一致，而String、Integer等类重写了equals()，改为比较内容。补充：String常量池特性（s1="abc"和s2=new String("abc")的区别）是高频延伸考点，s1指向常量池，s2指向堆内存，故s1==s2为false，s1.equals(s2)为true。
3. **String不可变的原因**：延伸考点，底层是final修饰的char数组（JDK9后为byte数组），无修改数组内容的公共方法，好处是线程安全、常量池复用、哈希值缓存，适合作为HashMap的key。


## 集合框架
1. **ArrayList与LinkedList的区别**：核心是底层结构。ArrayList基于动态数组，查询快、增删慢（尾部增删除外），默认初始容量10，扩容为1.5倍；LinkedList基于双向链表，查询慢、增删快，适合频繁增删的场景。
  - **非线程安全性下的核心表现**：ArrayList并发增删时，可能会因System.arraycopy()的数组复制操作导致元素覆盖，数组下标越界。LinkedList并发增删节点，会因多线程同时修改节点的prev/next指针，导致链表成环，节点丢失，遍历时报错。
2. **HashMap核心考点**：重点是底层实现和特性。JDK8后底层是“数组+链表+红黑树”，hashmap存储键值对，拿到键值后根据哈希函数计算得到数组下标，找到对应位置，如果位置为空则填入，如果不为空，则用拉链法形成链表。
  - **什么时候链表挥变成红黑树，什么时候红黑树会退化为链表**：链表节点大于8切数组长度大等于64链表变为红黑树，提升时间效率，红黑色节点小于6退化为链表，减少维护成本提高性能。
  - **扩容机制**：元素数量大于负载因子乘以当前容量，扩容两倍，保证容量始终是2的幂，才能用**位运算**代替取模。
  - **线程安全问题**：多线程可能死循环，数据覆盖。
  - **hash取值的平均O(1)怎么来的**：哈希表底层是数组 + 链表，通过哈希函数能一步定位到元素所在桶，正常情况下数据均匀分散，每个桶元素很少，所以平均查询 / 插入 / 删除都是 O (1)
3. **ConcurrentHashMap的线程安全实现**：JDK7：分段锁，粒度粗。JDK8：数组+链表+红黑树+**CAS+SYNchronized**，锁粒度细化到每个桶节点。锁粒度这样反而效率更高，100个线程操作100个不同的桶，彼此完全不阻塞，比分段锁（只有16把锁）并发度更高了
  - **并发手段**：volatile保证可见性，CAS无锁插入空桶，synchronized锁桶头结点。
4. **HashSet底层原理**：底层依赖HashMap，元素存储在HashMap的key中，value是固定的空对象，核心特性是“去重”，依赖equals()和hashCode()的重写。

## 面向对象
1. **重写（Override）与重载（Overload）的区别**：重写发生在**父子类**之间，方法名、参数列表、返回值必须一致，是运行期多态；重载发生在**同一类**中，方法名相同、参数列表不同（类型/数量/顺序），与返回值无关，是编译期多态。
2. **抽象类（abstract class）与接口（interface）的区别**：重点是设计目的和特性。抽象类可有普通方法、成员变量、构造器，只能单继承，体现“is-a”关系；接口JDK8后可有default/static方法，只能有常量，可多实现，体现“can-do”关系，核心是区分“代码复用”和“行为规范”的场景。
- **在项目中什么时候用抽象类和接口类**：接口定义行为规范，支持多实现，**优先使用**。让调用方只依赖接口，不依赖具体实现类，所以只要实现接口就能直接集成（解耦），**抽象类**封装共性代码，extends单继承，用于抽取公共逻辑。
3. **面向对象的三大特性**：分别是**封装、继承、多态**，封装是隐藏内部实现，暴露接口，保证数据安全；继承子类复用父类代码，支持扩展；多态编译器看类型，运行期看对象，就是同一个引用、同一个方法，表现不同行为 。
4. **反射**：在运行时动态获取类信息，调用方法，操作属性。要记一些他的方法，class.forName()，method.invoke()。
5. **泛型**：类型安全，避免强制类型转换。Java 泛型是给编译器看的，编译成字节码后，泛型信息会被擦掉，全部变成原始类型（比如 Object），这就叫**类型擦除**。eg：写代码时List<String，编译后List（和没泛型一样），运行时根本不知道你里面是 String。
6.   **基本类型和包装类型**:有八种，我就不罗列了，但是这边会考**为什么需要包装类型**：基本类型默认不能为null，且集合不能存储基本类型，所以有了包装类型
7.   **浅拷贝、深拷贝、零拷贝**：
- **浅拷贝**（Shallow Copy）核心是“**只拷贝对象本身，不拷贝对象内部的引用类型成员**”。实现方式：实现Cloneable接口，重写clone()方法（默认浅拷贝）。特点：原对象和拷贝对象共享引用类型成员，修改其中一个，另一个会受影响。
- **深拷贝**（Deep Copy）：核心是“**完全拷贝对象本身，以及对象内部所有引用类型成员，形成独立的新对象**”。实现方式：1. 重写clone()方法，对引用类型成员也进行拷贝；2. 通过序列化（Serializable）实现。特点：原对象和拷贝对象完全独立，互不影响，是面试重点。
- **临时拷贝**（：数据从磁盘-网卡，不经过用户态，不走CPU复制。实现map+write等
## 异常体系：
1. **异常分类**：顶层是**Throwable，分为Error和Exception**。Error是系统级错误（如OOM、StackOverflowError），程序无法处理；Exception是程序可处理的异常，分为受检异常（编译期必须处理，如IOException）和非受检异常（运行期异常，如NullPointerException、IndexOutOfBoundsException）。
2. **try-catch-finally执行顺序**：try先执行，catch捕获异常，finally无论是否发生异常都会执行，常用于资源释放，注意：finally中修改返回值会覆盖try/catch的返回结果（面试易踩坑）。

## 常见设计模式
1. **单例模式**：核心是“**一个类只有一个实例，且自行实例化并提供全局访问点**”。高频考点：懒汉式（线程安全/不安全）、饿汉式区别，双重检查锁实现方式，避免反射和序列化破坏单例。应用场景：工具类、线程池、配置类。
2. **策略模式**：核心是“**定义一系列算法，封装起来，让它们可以相互替换**”，分离算法的定义和使用。高频考点：核心角色（策略接口、具体策略、上下文），避免多重if-else。应用场景：支付方式选择（微信/支付宝/银行卡）、排序算法切换。

3. **工厂模式**：核心是“**通过工厂类创建对象，而非直接new**，降低耦合。高频考点：简单工厂（一个工厂创建所有对象，违反开闭原则）、工厂方法（一个工厂对应一个产品，符合开闭原则），应用场景：对象创建逻辑复杂、需要统一管理的场景（如日志工厂）。

4. **装饰器模式**：核心是“**动态给对象添加额外功能，不改变原对象结构**”，比继承更灵活。高频考点：核心角色（抽象组件、具体组件、装饰器），与继承的区别。应用场景：IO流（BufferedReader装饰InputStreamReader）、日志增强。

5. **观察者模式**：核心是“**定义对象间的一对多依赖，当一个对象变化时，所有依赖它的对象都会收到通知并更新**”。高频考点：核心角色（被观察者、观察者），应用场景：消息通知、事件监听（如Spring的事件机制）。

6. **代理模式**：核心是“**为目标对象提供一个代理对象，控制对目标对象的访问**”。高频考点：静态代理（编译期生成代理类）、动态代理（JDK动态代理/ASM/CGLIB），应用场景：Spring AOP、日志代理、权限控制。



## java的IO模型

常见的IO模型有四种：**BIO**（阻塞io），**NIO**（非阻塞的IO模型），**io多路复用**（用一个线程同时监听多个文件描述符，内核通知哪个就绪，就处理哪个），**AIO**（异步非阻塞，发起IO线程直接返回不等待，内核完成io，主动通知应用程序）。

IO操作完整的两个阶段：
1. **阶段1**，进行数据准备，内核把数据从磁盘/网盘加载到内核缓冲区。同时考虑阻塞还是非阻塞，进程在等待数据准备时，是否能做其他事。
2. **阶段2**，进行数据拷贝，内核把数据从内核缓冲区拷贝到用户进程的缓冲区。同时考虑是同步还是异步，数据拷贝的操作由谁完成，完成后是否需要进程主动感知。
# JVM

JVM（Java Virtual Machine，Java虚拟机）的核心作用是“**解释/编译Java字节码，让Java程序跨平台运行**”——不管是Windows、Linux还是Mac，只要安装了对应平台的JVM，相同的Java字节码就能运行出相同的结果，这也是“**一次编写，到处运行**”的核心原理。

## JVM的核心组成部分

这一节需要大家知道每个组件“是什么、做什么、核心考点是什么。
### JVM内存区域
JVM运行时，会划分出不同的内存区域，各司其职，核心是“**分离不同类型的数据，优化内存使用、避免混乱**”。重点掌握「运行时数据区」的划分（按线程是否共享，分为两大类），无需深入底层源码，理解功能和区别即可。
1. **线程共享区域**（所有线程共用，生命周期与JVM一致）
        
  - **方法区**（Method Area）：存储类信息（类名、方法、字段）、常量、静态变量、即时编译后的代码等。JDK8后，方法区的实现是“元空间（Metaspace）”，取代了之前的永久代，核心区别是：元空间使用本地内存，不再占用JVM堆内存，避免OOM（OutOfMemoryError）。

  - **堆**（Heap）：JVM内存中最大的一块，核心用于存储对象实例（几乎所有new出来的对象都在这里），是垃圾回收（GC）的核心区域。堆又分为年轻代（Eden区、Survivor区）和老年代，后续讲垃圾回收时会串联，这里先记住：堆是GC的主要战场。
2. **线程私有区域**（每个线程独有，生命周期与线程一致，线程结束后释放）
        
  - **程序计数器**（Program Counter Register）：最小的一块内存，用于记录当前线程执行的字节码行号（比如“下一条要执行的指令是什么”），唯一不会出现OOM的内存区域。
  - **虚拟机栈**（VM Stack）：存储线程执行方法时的“栈帧”（每个方法执行时，都会创建一个栈帧，存储局部变量、方法出口等），栈深度过大时会出现StackOverflowError（比如递归调用没有终止条件）。
  - **本地方法栈**（Native Method Stack）：与虚拟机栈功能类似，区别是：虚拟机栈服务Java方法，本地方法栈服务Native方法（比如Java调用C/C++的方法），同样可能出现StackOverflowError和OOM。

### 类加载机制
Java文件**（.java）**编译后会生成字节码文件**（.class）**，JVM要运行程序，必须先将.class文件加载到内存中，这个过程就是“**类加载**”，核心是“**将类的二进制数据加载到方法区，生成Class对象**”。
核心流程（由浅入深，记住这5步即可）：**加载 → 验证 → 准备 → 解析 → 初始化**（面试常考流程顺序）。

1. **加载**：找到.class文件（从本地磁盘、网络等），读取二进制数据，在内存中生成Class对象（存储在方法区），是类加载的第一步。

2. **验证**：校验.class文件的合法性（比如是否符合Java规范、是否被篡改），避免恶意字节码危害JVM安全，是安全校验环节。

3. **准备**：为类的静态变量分配内存（存在方法区），并设置默认初始值（比如int默认0，String默认null），注意：此时不会执行静态代码块。

4. ** 解析**：将类中的符号引用（比如类名、方法名）替换为直接引用（内存地址），让JVM能直接找到对应的类和方法。

5. **初始化**：执行静态变量赋值和静态代码块，这是类加载的最后一步，也是类真正“可用”的标志（只有初始化完成后，才能创建对象、调用方法）。

**补充：**类加载器（ClassLoader）——负责“加载”步骤，核心分为3类（引导类加载器、扩展类加载器、应用类加载器），遵循“**双亲委派模型**”（先让父加载器加载，父加载器加载不了再由子加载器加载），目的是避免类重复加载、保证核心类的安全（比如Java核心类不会被自定义类篡改）。

### 执行引擎（了解即可，问的比较少）
类加载完成后，JVM需要执行字节码，执行引擎就是负责这项工作的核心组件，核心有两种执行方式（由浅到深）：
1. **解释执行**：逐行解析字节码，执行一行、解释一行，优点是启动快，缺点是执行效率低（适合启动阶段、代码片段较少的场景）。
2. **编译执行**：通过即时编译器（JIT，Just-In-Time Compiler），将频繁执行的字节码（热点代码）编译成机器码，缓存起来，后续执行直接调用机器码，优点是执行效率高，缺点是启动时需要编译，启动速度慢。

### 垃圾回收
堆和方法区是线程共享区域，会产生内存垃圾（**比如不再使用的对象、废弃的类**），如果不清理，会导致**内存溢出（OOM）**，垃圾回收就是负责“**自动清理垃圾、释放内存**”的组件，无需程序员手动释放（这也是Java比C/C++更易用的原因之一）。
浅度重点（先掌握3个核心问题）：
1. **垃圾是什么**？——不再被引用的对象（比如对象引用为null、超出作用域）。

2. **如何判断垃圾**？——核心两种方式：引用计数法（简单但有循环引用问题）、可达性分析（JVM实际使用，以GC Roots为起点，无法到达的对象视为垃圾）。

3. **垃圾怎么回收**？——核心垃圾回收算法：标记-清除算法（简单但产生碎片）、复制算法（无碎片但浪费内存，用于年轻代）、标记-整理算法（无碎片，用于老年代）、分代收集算法（JVM实际使用，结合年轻代和老年代的特点，搭配不同算法）。

**补充**：垃圾回收器（GC收集器）——是垃圾回收算法的具体实现，比如Serial GC、Parallel GC、CMS GC、G1 GC（面试高频），不同收集器的性能、适用场景不同，后续串联整体框架时再展开。

### 字节码与常量池
**Java代码编译后生成的字节码**，是JVM能识别的“中间语言”（不是机器码），包含类的结构、方法、指令等信息；**常量池**（分为静态常量池和运行时常量池）存储类中的常量、字符串、符号引用等，是类加载和执行的重要依赖。

## JVM的运行框架
这部分讲这些组件如何协同工作，完成Java程序的运行。
### 整体流程
1. **编写Java代码**：开发者编写.java源文件（比如HelloWorld.java）。
2. **编译**：通过javac编译器，将.java文件编译成字节码文件（.class文件），此时生成的.class文件包含字节码、静态常量池等信息。

3. **类加载**：JVM的类加载器（ClassLoader）按照“双亲委派模型”，将.class文件加载到内存，经过“加载→验证→准备→解析→初始化”5个步骤，在方法区生成Class对象，同时将静态常量池的内容加载到运行时常量池。

4. **内存分配**：程序执行时，创建对象（new Object()），JVM在堆中为对象分配内存，同时在虚拟机栈中创建栈帧（存储局部变量、方法调用信息），程序计数器记录当前执行的字节码行号。

5. **执行字节码**：执行引擎通过“解释执行+编译执行”结合的方式，执行字节码（热点代码由JIT编译成机器码缓存），期间调用本地方法时，会使用本地方法栈。

6. **垃圾回收**：堆和方法区中产生的垃圾（不再被引用的对象、废弃的类），由垃圾回收器（GC）按照对应的回收算法自动清理，释放内存，避免OOM。

7. **程序终止**：所有线程执行完毕，JVM销毁各个内存区域，程序运行结束。

## 核心组件的协同关系

**类加载器**将字节码加载到方法区，**执行引擎**读取字节码，在**虚拟机栈、程序计数器**的配合下执行方法，对象存储在**堆**中，**垃圾回收器**负责清理堆和方法区的垃圾，所有组件协同工作，实现Java程序的跨平台运行。
补充3个核心关联：
1. **类加载与内存区域**：类加载的最终结果是在方法区生成Class对象，静态变量存储在方法区，对象实例存储在堆，局部变量存储在虚拟机栈。

2. **执行引擎与垃圾回收**：执行引擎执行字节码时，会不断创建对象，产生垃圾，垃圾回收器在后台运行，当堆内存不足时，触发垃圾回收，清理垃圾后，执行引擎继续执行程序。

3. **内存区域与OOM**：不同内存区域的OOM原因不同（比如堆内存不足导致OOM、元空间不足导致OOM、虚拟机栈深度过大导致StackOverflowError），这是面试高频延伸题，后续可深入。

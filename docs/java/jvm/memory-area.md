# JVM 内存区域详解

> 配套：[JVM 总览](./) Q1 已讲五大区域概览。本篇深入：**每个区域的内部结构 + 各自的 OOM 触发条件 + 对象创建过程 + 逃逸分析与栈上分配**。

---

## Q1：五大区域内部结构？

**答**：

**程序计数器**（线程私有）：一块记录「当前线程执行的字节码行号」的内存。线程切换后能恢复到正确位置。**唯一不会 OOM** 的区域。

**虚拟机栈**（线程私有）：由一个个**栈帧**组成，每个方法调用 = 压一个栈帧，方法返回 = 弹出。栈帧含四部分：
- 局部变量表（存方法参数 + 方法内局部变量，基本类型直接存值，引用存指针）
- 操作数栈（执行字节码的工作区，如 `a+b` 先压 a、压 b、加、弹结果）
- 动态链接（指向运行时常量池的方法/字段引用）
- 返回地址（方法返回后回到调用方的位置）

**本地方法栈**（线程私有）：native 方法的栈，和虚拟机栈结构一样，只是服务 native。

**堆**（共享）：所有对象实例 + 数组。GC 主战场。可分新生代（Eden + S0 + S1）+ 老年代。

**方法区**（共享）：类元信息（Class 结构）、运行时常量池、静态变量、JIT 编译后的本地代码（JDK 8+ 移到 CodeCache，但广义算方法区范畴）。

## Q2：每个区域什么情况会 OOM / 栈溢出？

**答**：

| 区域 | 异常 | 触发场景 |
|---|---|---|
| 程序计数器 | （不溢出） | — |
| 虚拟机栈 | `StackOverflowError` | 方法递归过深（无正确终止条件的递归） |
| 虚拟机栈 | `OutOfMemoryError` | 栈帧太大或线程太多（每线程占栈空间，`-Xss` 越大单线程栈越大，能建的线程数越少） |
| 堆 | `OutOfMemoryError: Java heap space` | 对象太多/内存泄漏（如 HashMap 只 put 不 remove） |
| 方法区/元空间 | `OutOfMemoryError: Metaspace` | 动态生成大量 Class（CGLIB、字节码增强未控制）、或加载过多类 |
| 直接内存 | `OutOfMemoryError: Direct buffer memory` | NIO 的 ByteBuffer.allocateDirect 用太多没释放 |

**易错点**：栈的两种异常要分清——**StackOverflowError** 是单线程递归太深（栈帧超过栈大小）；**OOM** 是总栈空间不够（线程数 × 单栈大小 > 进程可用内存）。调大 `-Xss` 反而让可建线程数变少（更易线程 OOM）。

## Q3：对象创建过程？

**答**：`new Object()` 在 JVM 内部：

1. **类加载检查**：常量池里类的符号引用是否已加载/解析/初始化，没有先触发类加载。
2. **分配内存**：在堆划一块给对象。两种方式：
   - **指针碰撞**：堆规整（内存连续，一侧空闲一侧已用），指针往空闲侧挪对象大小。要求 GC 带 Compact（Serial/ParNew 配 Compact）。
   - **空闲列表**：堆不规整（碎片），维护一个「哪些块空闲」的列表，找一块够大的。CMS 用这种方式（标记-清除有碎片）。
3. **内存清零**：分配的内存清零（基本类型默认 0、引用默认 null 的来源）。
4. **设置对象头**：填 Mark Word（哈希、GC 年龄、锁状态）+ 类元信息指针。
5. **执行 `<init>`**：构造方法初始化。

**TLAB**（Thread Local Allocation Buffer）：堆是共享的，多线程分配内存要竞争指针。JVM 给每线程在 Eden 区预分配一小块（TLAB），线程在自己的 TLAB 里分配（无竞争），用完了再申请新 TLAB 或全局竞争。**绝大多数对象在 TLAB 分配，无锁**。

**易错点**：「指针碰撞 vs 空闲列表」取决于**堆是否规整**，而堆规整取决于**GC 是否 Compact**。CMS 用标记-清除（不 Compact）→ 碎片 → 空闲列表；G1 用复制+整理（规整）→ 可用指针碰撞。这是「GC 选择影响分配方式」的链条。

## Q4：逃逸分析与栈上分配

**答**：JIT 编译时做**逃逸分析**（Escape Analysis），分析对象的作用域：

- **未逃逸**（对象只在方法内用，没传出）：JVM 可能**直接在栈上分配**（不进堆），方法结束栈帧弹出对象自动消失，**无需 GC**。
- **方法逃逸**（对象被 return 或存到字段）：必须在堆分配。
- **线程逃逸**（对象被其他线程访问）：堆 + 同步。

**标量替换**：未逃逸的对象如果可拆成基本类型（标量），JVM 把字段打散成局部变量，连对象都不建（彻底无对象）。

**易错点**：栈上分配/标量替换是 **JIT 优化**，不是语言保证。`-XX:-DoEscapeAnalysis` 关掉后就退回堆分配。所以「对象一定在堆」**不严谨**——多数对象在堆，未逃逸的小对象可能被优化到栈。面试答「理论上堆，但 JIT 逃逸分析可让未逃逸对象栈上分配」更准。

## Q5：堆和元空间的调参？

**答**：
- **`-Xms` / `-Xmx`**：堆最小 / 最大。生产建议**相等**（避免运行时扩容抖动）。
- **`-Xmn`**：新生代大小。或用 `-XX:NewRatio=2`（老:新 = 2:1）。
- **`-XX:SurvivorRatio=8`**：Eden : Survivor = 8:1（两个 S 共占 2，Eden 占 8，总新生代 10 份）。
- **`-XX:MetaspaceSize` / `-XX:MaxMetaspaceSize`**：元空间初始 / 最大。元空间在本地内存，默认上限受系统内存限制，**生产建议设上限**（防类泄漏吃光内存）。
- **`-Xss`**：单线程栈大小，默认 512KB~1MB。栈越大递归越深但线程数越少。

**易错点**：`-Xms == -Xmx` 避免扩容抖动，但**初始化时就占满**（操作系统看 JVM 进程内存 = Xmx，即使实际没用）。容器环境（Docker memory limit）要注意 Xmx 别超过容器配额，否则 OOM Killer 杀进程。

## 易错点速查表

| 知识点 | 关键 |
|---|---|
| 程序计数器 | 唯一不 OOM |
| 栈帧 | 局部变量表 + 操作数栈 + 动态链接 + 返回地址 |
| 栈异常 | StackOverflow（递归深）vs OOM（线程多） |
| 调 -Xss | 越大单栈越深，但可建线程数越少 |
| 对象分配 | 指针碰撞（规整）vs 空闲列表（碎片）；TLAB 无锁 |
| GC 影响 | CMS 碎片→空闲列表；G1 规整→指针碰撞 |
| 栈上分配 | JIT 逃逸分析优化，不是保证；未逃逸才栈上 |
| 元空间 | 本地内存（JDK 8+），生产设 MaxMetaspaceSize 防泄漏 |
| Xms==Xmx | 防扩容抖动，但初始化占满，容器注意配额 |

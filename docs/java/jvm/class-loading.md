# 类加载（5 阶段 / 双亲委派 / 打破场景）

> 配套：[JVM 总览](./) Q5 已讲类加载概览 + 双亲委派。本篇深入：**5 阶段每步做什么、双亲委派为什么、Tomcat/SPI/JDBC 怎么打破、什么时机触发初始化**。

---

## 思考锚点

Java 程序里，我们写的 `.class` 文件需要被加载到 JVM 内存中才能执行。但加载不是简单的「读文件」——JVM 设计了一套严格的类加载机制，既要保证安全（防止用户伪造核心类），又要保证同一个类全局唯一。

这套机制的核心就是「双亲委派」：加载一个类时先让父加载器尝试，父加载不了才自己加载。但在某些场景下（如 Tomcat 多应用隔离、SPI 机制），必须打破这套规则。

本文要讲清楚类加载的 5 个阶段、双亲委派的设计初衷、怎么打破它，以及自定义加载器的正确姿势。

## Q1：类加载 5 阶段详解

**答**：
1. **加载**：通过全限定名获取字节流（jar/网络/动态生成），转为方法区的运行时数据结构，堆里生成 Class 对象作为访问入口。
2. **验证**：检查字节码合法性（格式/元数据/字节码/符号引用），防恶意字节码崩 JVM。
3. **准备**：为**静态变量**分配内存 + **赋默认零值**（int=0, 引用=null）。例外：`static final` 常量（ConstantValue 属性）在准备阶段就赋真值。
4. **解析**：常量池的符号引用替换为直接引用（方法符号 → 内存偏移）。可能懒解析（首次用到才解析）。
5. **初始化**：执行 `<clinit>`——静态变量赋真值 + static 块。JVM 保证 `<clinit>` 线程安全（多线程只一个执行，其他阻塞）。

**易错点**：准备阶段 static 变量是**默认零值**，初始化阶段才赋真值。`static int x = 10`：准备 x=0，初始化 x=10。`static final int x = 10`（常量）：准备阶段直接 x=10（ConstantValue 例外）。

## Q2：双亲委派 + 为什么

**答**：类加载请求先委派**父加载器**，父加载不了才自己加载。层级：启动类加载器（`rt.jar`）→ 扩展/平台类加载器（`ext`）→ 应用类加载器（classpath）→ 自定义。

**为什么**：
1. **安全**：防止用户伪造 `java.lang.Object`——用户写的 Object 会被启动类加载器先加载真的，用户的被忽略。
2. **唯一性**：同一 Class 全局只加载一次（同一字节码只一份 Class 对象），避免重复 + 类型不一致。

**易错点**：双亲委派**不是强制的**——是 `ClassLoader.loadClass` 的默认实现，可重写打破。JDK 9+ 模块化对层级有调整（变平），但核心思想不变。

## Q3：双亲委派怎么打破？

**答**：重写 `loadClass`（委派逻辑），改成「先自己加载，加载不了再委派父」。三个典型场景：

**Tomcat**：每个 webapp 一个 `WebappClassLoader`，**先自己加载** `WEB-INF/classes` 和 `lib`。原因：多个 webapp 可能依赖同一库的不同版本（webapp A 的 Spring 5 和 B 的 Spring 4），必须隔离。

**SPI（Service Provider Interface）**：接口在 `rt.jar`（启动类加载器加载），实现在 classpath（应用类加载器）。启动类加载器看不到 classpath 实现，用**线程上下文类加载器**（默认应用类加载器）反向加载。典型：JDBC 的 `DriverManager`（rt.jar）加载 classpath 的 MySQL Driver。

**OSGi**：网状委派（模块间按规则互相委派，不是树形）。

**易错点**：SPI 的「线程上下文类加载器」是**逆向**的（父请求子加载），违背双亲委派方向。这是双亲委派局限性（父看不到子）的妥协方案，不是优雅解，是工程补丁。

## Q4：什么时机触发类初始化（`<clinit>`）？

**答**（6 种「主动使用」）：
1. `new` 创建实例 / 访问静态字段（非 final 常量）/ 调用静态方法。
2. 反射（`Class.forName`）。
3. 初始化子类时，父类若未初始化先触发父类初始化。
4. JVM 启动主类（含 main 的类）。
5. `MethodHandle` 句柄对应的类。
6. 接口含 default 方法时，实现类初始化触发接口初始化。

**不触发初始化**：
- 通过子类名访问**父类**的静态字段（只触发父类，不触发子类）。
- `ClassName[] arr = new ClassName[10]`（数组创建不触发元素类初始化，数组类型是 JVM 生成的）。
- 访问 `static final` 常量（编译期能确定的，直接进常量池，不触发初始化）。

**易错点**：`Class.forName("X")` 默认触发初始化；`Class.forName("X", false, loader)` 不触发。框架延迟初始化常用后者（Spring 的 lazy bean 定义）。

## Q5：自定义类加载器注意什么？

**答**：继承 `ClassLoader`，**重写 `findClass`**（保留双亲委派）或 `loadClass`（打破委派）。

- **重写 `findClass`**：父加载不了时才调 `findClass`，双亲委派保留。适用于「加密类文件（加载时解密）」「从非标准源加载（网络/数据库）」。
- **重写 `loadClass`**：完全接管加载顺序，打破委派。适用于「隔离（Tomcat webapp）」「热部署」。

**易错点**：自定义加载器**默认重写 `findClass`**，不要动 `loadClass`——`loadClass` 含委派逻辑，重写它就打破委派，除非你有明确的隔离需求（如 Tomcat）。乱重写 `loadClass` 会导致「核心类被自定义加载器加载」，破坏唯一性，引发 `ClassCastException`（同名字节码不同加载器加载 = 不同 Class）。

## 易错点速查表

| 知识点 | 关键 |
|---|---|
| 准备阶段 | static 默认零值；`static final` 常量直接赋真值 |
| 初始化 `<clinit>` | 线程安全；static 赋真值 + static 块 |
| 双亲委派 | 安全（防伪造）+ 唯一性；重写 `loadClass` 可打破 |
| Tomcat | webapp 先自己加载（隔离多版本） |
| SPI | 线程上下文类加载器逆向加载（父求子，工程补丁） |
| 主动使用 | new/反射/静态访问/子类初始化触发父类 |
| 不触发 | 数组创建 / 访问 final 常量 / 子类访问父类静态 |
| 自定义加载器 | 重写 `findClass`（保留委派），别动 `loadClass`（除非隔离） |

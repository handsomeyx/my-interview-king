# JVM

> Java 面试 TOP2。JVM 题考察三块：**内存区域（哪里存）、GC（怎么回收）、类加载（怎么加载）**。本文按问答组织，每题答 + 追问 + 易错点。

## 体系速览

```
JVM 三大块
├── 内存区域
│   ├── 线程私有：程序计数器、虚拟机栈、本地方法栈
│   └── 线程共享：堆、方法区(JDK8+ 元空间)
├── GC
│   ├── 判活：可达性分析(GC Roots)
│   ├── 算法：标记-清除 / 复制 / 标记-整理
│   └── 收集器：Serial / ParNew / Parallel / CMS / G1 / ZGC
└── 类加载
    └── 加载 → 链接(验证/准备/解析) → 初始化；双亲委派
```

## Q1：JVM 内存区域？

**答**：
- **程序计数器**（线程私有）：记录当前字节码行号。**唯一不会 OOM** 的区域。
- **虚拟机栈**（线程私有）：方法调用的栈帧（局部变量表/操作数栈/动态链接/返回地址）。递归过深 → `StackOverflowError`；栈帧太大或线程太多 → `OutOfMemoryError`。
- **本地方法栈**（线程私有）：native 方法的栈。
- **堆**（共享）：对象实例 + 数组。GC 主战场。OOM。
- **方法区**（共享）：类元信息、常量池、静态变量。JDK 7- 是永久代（PermGen，堆内）；JDK 8+ 改元空间（Metaspace，本地内存）。

**易错点**：**方法区 ≠ 永久代 ≠ 元空间**。方法区是 JMM 规范定义的逻辑区域；永久代是 JDK 7 前的实现（堆内、固定大小易 OOM）；元空间是 JDK 8+ 的实现（本地内存、默认不限，但可配 MaxMetaspaceSize）。三个词常被混用，面试要分清。

## Q2：GC Roots 有哪些？

**答**：可达性分析的起点，包括：
- 虚拟机栈中引用的对象（方法局部变量、参数）
- 方法区中类静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈 JNI 引用
- JVM 内部引用（基本类型 Class、常驻异常、类加载器）
- synchronized 持有的对象

**追问**：哪些**不算** GC Roots？→ 已出作用域的局部变量、被弱/软引用关联的对象（可达性分析时按引用强度决定是否回收）。

## Q3：GC 算法？

**答**：
- **标记-清除**（Mark-Sweep）：标记存活、清除其他。缺点：碎片。
- **复制**（Copying）：分两块，存活挪到另一块清空原块。缺点：空间利用率 50%。新生代用（Eden:S0:S1 = 8:1:1，实际浪费 10%）。
- **标记-整理**（Mark-Compact）：标记存活、向一端移动。无碎片但要移动对象。老年代用。
- **分代收集**：新生代（朝生夕死、存活少）用复制；老年代（存活久）用标记-清除/整理。

**易错点**：新生代用复制算法**不是因为「对象多」**，而是「存活少」——复制成本正比于存活对象数，存活少则复制成本低。

## Q4：常见垃圾收集器？

**答**：
| 收集器 | 作用代 | 特点 |
|---|---|---|
| Serial / Serial Old | 新 / 老 | 单线程，Client 模式用 |
| ParNew | 新 | 多线程并行，常配 CMS |
| Parallel Scavenge / Parallel Old | 新 / 老 | 多线程并行，**吞吐量优先**（JDK 8 默认） |
| CMS | 老 | 并发、低停顿（4 阶段）。JDK 9 弃用、14 移除 |
| G1 | 新+老 | 分 Region、可预测停顿。**JDK 9+ 默认** |
| ZGC / Shenandoah | 全 | 染色指针/读屏障，停顿 <10ms |

**追问**：G1 和 CMS 区别？→ G1 把堆分成 Region（不再物理固定新生代/老年代），可设停顿目标（`-XX:MaxGCPauseMillis`），用复制+整理无碎片；CMS 用标记-清除，有碎片且并发失败会退化为 Serial Old（Full GC 停顿长）。

## Q5：类加载机制和双亲委派？

**答**：类加载 5 阶段：**加载**（找字节流生成 Class）→ **验证** → **准备**（静态变量赋默认值，如 int=0）→ **解析**（符号引用→直接引用）→ **初始化**（静态变量赋真值 + static 块）。验证+准备+解析合称「链接」。

**双亲委派**：类加载请求先委派父加载器，父加载不了才自己加载。层级：启动类加载器（`rt.jar`）→ 扩展类加载器（`ext`）→ 应用类加载器（classpath）→ 自定义。

**追问**：为什么要双亲委派？→ **安全**（防止用户伪造 `java.lang.Object`）+ **避免重复加载**（同一个 Class 全局只加载一次，保证唯一性）。

**易错点**：双亲委派**不是强制**的，可打破：
- **Tomcat**：每个 webapp 独立 ClassLoader，先自己加载（打破委派），实现 webapp 隔离。
- **SPI**（如 JDBC）：接口在 `rt.jar`（启动类加载器加载），实现在 classpath（应用类加载器），用**线程上下文类加载器**反向加载。
- **OSGi**：网状委派。

## Q6：强/软/弱/虚引用？

**答**：
- **强引用**（普通 `new`）：只要强可达就不回收。OOM 也不回收。
- **软引用**（`SoftReference`）：内存不足时才回收。适合**内存敏感的缓存**。
- **弱引用**（`WeakReference`）：下次 GC 就回收（无论内存够不够）。`WeakHashMap`、`ThreadLocal` 的 key。
- **虚引用**（`PhantomReference`）：形同虚设，get 总返回 null，只跟踪对象被回收的事件（配合 ReferenceQueue 做资源清理）。

**易错点**：ThreadLocal 的 key 是**弱引用**（ThreadLocal 实例回收后 key=null），但 value 是**强引用**——这是 ThreadLocal 内存泄漏的根源（见 [并发篇](../concurrent/) Q7）。

## 易错点速查表

| 知识点 | 关键 |
|---|---|
| 程序计数器 | 唯一不 OOM 的区域 |
| 方法区 | JDK 7- 永久代（堆内）；JDK 8+ 元空间（本地内存） |
| 新生代复制算法 | 因「存活少」成本才低，不是「对象多」 |
| CMS vs G1 | CMS 标记清除有碎片；G1 复制+整理无碎片，分 Region |
| JDK 默认收集器 | JDK 8 Parallel Scavenge+Old；JDK 9+ G1 |
| 双亲委派 | 可打破（Tomcat/SPI/OSGi） |
| finalize | 已弃用（不可靠），用 try-with-resources / Cleaner |
| 引用强度 | 强 > 软 > 弱 > 虚 |

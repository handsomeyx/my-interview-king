## 操作系统基础

### 1.1什么是操作系统？

操作系统就是计算机硬件和应用软件之间的桥梁，windows、linux都是操作系统，像个智能管家，负责协调所有的硬件，调度应用软件，让他们有序运行，避免争抢。

所以，当被问到“**操作系统的核心功能是什么**？“ ，一定要想到管理：进程/线程管理、内存管理、文件管理、设备管理、用户接口管理。

### 1.2操作系统的运行机制

这部分是后续进程、内存管理的基础，核心呢就是**特权级**和**中断机制**。

首先讲一下**特权级**，CPU会将指令分为特权指令和非特权指令，对应操作系统的**内核态和用户态**。**内核态拥有最高权限**，可以执行所有指令；**用户态代表应用程序的状态**，智能执行非特权指令。所以，如果用户态要访问硬件资源（读写文件，分配内存）必须通过**系统调用**想内核发起请求，进行**特权切换**。所以**系统调用也是有代价的哦**：切换的话需要保存上下文，消耗CPU资源，高频调用会影响性能，会受到

而CPU在执行程序，突然收到外部信号（比如我现在正在输入某条指令，或者硬件故障率）会展厅当前程序，去执行对应中断处理程序。分为硬中断和软中断，仅做了解。

## 进程与线程（与协程）（重点）

这部分八股会问，项目拷打时也会问，太重要了。

### 进程
简单讲一下，进程就是一个**正在进行的程序**，比如打开微信了，微信就是一个进程，每个进程都有自己**独立的地址空间**，是操作系统进行资源分配和调度的基本单元。

**进程的生命周期**：创建——就绪——运行——阻塞——终止。容易考到的就是**进程的创建方式**，fork()创建子进程。**进程的终止方式**：正常终止、异常终止、强制终止。

### 线程

每个进程都有独立地址空间，切换时需要保存/恢复整个进程的上下文（进程被切换走后，要保存的当前和后面接受到的所有信息），那会消耗大量的CPU啊，代价太大了。所以**线程**出现了——它是进程的一个执行单元，一个进程可以包含多个线程，所有线程共享进程的地址空间、资源，且独立运行，是调度的基本单元。这样我切换代价就小了，线程只需保存/恢复线程自身的寄存器和PC就可以了。

前面说微信是一个进程的话，那么当你打开微信，可能同时在收信息，刷朋友圈，那收信息是一个线程，晒朋友圈也是一个线程。这些线程各干各的或，同时并行干活，效率更高。

线程虽然比进程轻量，但是仍受**操作系统内核调度（属于内核态线程）**，因为线程是 CPU 调度的最小单位，必须让操作系统内核知道它的存在，由内核统一分配 CPU 时间。而切换时需要从用户态切换到内核态，存在一定的切换开销。既然多个线程共享资源了，那必然会有资源争抢的问题。比如两个线程同时修改一个全局便令，会导致数据不一致，这就需要**同步与互斥**机制，保证资源有序访问：
- **互斥**：多个进程/线程不能同时访问同一个共享资源，就是“排他性”
- **同步**：多个进程/线程，按一定顺序执行，就是“有序性”

咋实现呢？四种方法：有兴趣的同学可以自行去了解：**信号量，互斥锁，条件变量，管程**

再来讲讲**进程/线程怎么调度**：
- FCFS，先来先服务：进程/线程谁先到就绪队列，先到先执行。适合**批处理**，同时对响应时间要求不高。优点：简单呗。缺点：短作业容易被长进程阻塞。
- SJF，短作业优先：这时候短作业先做，适合短作业多的场景，可以缩短平均响应时间，但是对长作业也不公平
- **RR** 时间片轮转：CPU时间片平均分给就绪队列中的所有进程/线程。公平，无饥饿。缺点就是这个时间片的时长划分，太短上下文切换频繁，过长短进程响应时间过长
- **优先级调度**：每个进程/线程分配一个优先级，数字越大，优先级越高。优点：能保证核心进程优先执行，满足实时需求。缺点：低优先级进程可能饥饿。

### 死锁
而当多个进程/线程互相等待对方持有的对方等待资源，无法继续执行，先入永久阻塞的状态，我们称为**死锁**。

死锁的四个必要条件：
- **互斥**：资源具有排他性，同一个时刻只能被一个进程/线程访问
- **请求与保持条件**：进程/线程已经持有部分资源，又去申请其他啊资源，同时不释放自己已持有的资源
- **不可剥夺**：进程/线程持有的资源，不能被其他强制剥夺，只能自己主动释放
- **循环等待**：多个进程/线程之间，形成一个资源等待循环

怎么解决死锁呢？
- **破坏四个必要条件之一**：我们**最常用、最推荐**的预防状态就是对所有资源编号，进行和现场必须按照从小到大的顺序申请资源，来破坏循环等待的条件。
- **动态检测，提前规避**：进程/线程申请资源时候，操作系统动态检测“如果分配资源，是否会产生死锁”如果会，就拒绝分配，反之分配。
- **死锁发生，强制解决**：强制终止一个或多个死锁机场南，释放资源；强制剥夺死锁进程持有的资源，分配给其他死锁进程。

### 协程

在超高并发，IO密集型任务来说，线程切换开销依然会成为瓶颈，所以这时候我们就需要一个比线程更“轻量”的并发载体了，那就是**协程**，完全由用户态调度，隶属线程，一个线程可以有多个协程。它具备以下核心的特性：
- **超轻量级**：协程的创建成本极低，一个线程可以创建上万个协程
- **用户态调度**：协程切换无需内核参与，完全用户态完成，切换开销几乎可以忽略
- **依赖IO等待切换**：协程优势主要体现在IO密集型任务，当一个协程执行IO操作时，主动切换到其他协程执行，避免CPU空闲
- **不适合CPU密集型任务**：协程运行在单个线程中，同一时刻只有一个协程在执行。若任务是CPU密集型，协程无法利用多核CPU，性能不如多线程/进程。

### 如何判断项目是多进程、多线程、多协程呢？

咳咳，如果项目是自己做的话，应该都清楚，但是如果是包装的，懂得都懂。这方面我就曾经被字节拷打过，还好当时蒙对了。吸取教训，这节内容教大家如何判断自己的项目的部署。

#### 维度1.看你的代码

我这里就举例java
**多进程判断**：
- 使用java.lang.ProcessBuilder、Runtime.exec()创建子进程，或通过JVM的多进程部署（比如多个Tomcat实例）

**多线程判断**：
- 使用java.lang.Thread类、ExecutorService线程池（ThreadPoolExecutor）、Callable/Future。

**多协程判断**：
- Java没有原生协程，需借助第三方库（比如Quasar），或使用Project Loom的VirtualThread（虚拟线程，本质是JVM层面的协程）。

#### 维度2.看运行特征

**多进程判断**：
- 内存占用高，每个进程占用独立内存，若项目有多个进程，系统内存会被多个进程分别占用。
- 一个进程崩溃，其他进程正常运行
- 并发量适中，一般并发量在几百以内，适合CPU密集型任务

**多线程判断**：
- 内存占用中等，比如100个线程，内存占用只有100MB左右，
- 崩溃影响大，一个线程崩溃，整个进程崩溃，在java Web项目，一个请求线程抛出异常未经处理，整个Tomcat进程可能挂
- 并发量高：适合IO密集型+中等CPU负载的任务

**多协程判断**：
  - 内存占用极低：上万个协程的内存占用，仅相当于一个线程的内存（比如Python中，一个协程占用几KB内存，10万个协程仅占用几十MB）。
  - 并发量极高：适合超高并发的IO密集型任务（比如高并发爬虫、即时通讯服务、API网关），并发量可达几十万甚至上百万。
  - CPU利用率稳定：协程切换开销极低，CPU主要用于处理业务逻辑，而非切换，即使并发量高，CPU利用率也不会过高（除非有CPU密集型任务）。


#### 维度3：看系统监控
**多进程判断**：
- Linux：使用ps -ef|grep项目名称，查看进程数量
- windows：打开任务管理器，查看“进程”选项卡
- 
**多线程判断**：
- Linux:使用pstack进程ID或查看单个进程下的线程数量，若线程数量大于1，则为多线程
- Windows：任务管理器中，选中进程，右键打开文件所在位置的详细信息
- 
**多协程判断**：
- 若项目单个线程下的执行单元数量远超线程数量，则大概多协程。python项目大多使用。

#### 维度4：结合具体的场景

- **web服务器**：Nginx默认多进程，Tomcat默认多线程
- **数据库**：MySQL多线程，Redis单线程+多协程
- **CPU密集型任务**：大概率是多进程。






同时这边结合数据层面进行扩展考察：
- **为什么Redis用单线程+IO多路复用？**因为Redis的瓶颈在IO，而非CPU，单线程可以避免线程切换的代价
- **为什么Mysql用多线程？** 因为Mysql的查询和Io操作可以并行，多线程可以并发处理能力。

## 内存管理

### 内存管理的核心目标

操作系统管理内存主要实现三个目标：**内存利用率最大化**，**进程隔离（多个进程共享内存，但各自的地址相互独立）**，**地址映射（将逻辑地址隐射到物理地址）**

### 逻辑地址和物理地址
这块要搞清楚，否则后续分页、虚拟内存听不懂。
- **逻辑地址**：也叫虚拟地址，进程运行时，自身代码中的地址，进程并不知道实际的物理地址
- **物理地址**：是内存硬件的实际地址，是唯一的，操作系统能通过物理地址直接访问

进程执行时，CPU会将进程的逻辑地址，通过“地址映射机制”（比如分页、分段），转换成物理地址，再访问内存。这样做的好处是“进程无需关心物理内存的分配，只需使用自己的逻辑地址，实现进程隔离”​。

### 分页/分段存储管理
早期内存管理是为每个进程分配一块连续的物理内存，进程A分配物理地址0x1000~0x2000，进程B分配0x2001~0x3000。优点是简单，但是缺点很明显，**容易产生内存碎片**，频繁的分配和释放内存后，会产生大量空闲但无法利用的小内存块（比如释放0x1000~0x1500和0x1600~0x2000，中间的0x1501~0x1599是空闲碎片，无法分配给需要100字节的进程）。

为了解决连续内存分配的**内存碎片问题**，**分页存储管理**应运而生，将逻辑地址和物理地址都分成固定大小的快，逻辑地址的快叫**页面**，物理地址的快叫**页框**，页面大小和页框大小一致。

分页的**优点**在于：解决了内存碎片问题——页面可以分散在不同的页框中，无需连续；内存利用率也高；而且能运行大内存，只要有足够的页框，即使不连续，也能分配。**缺点**也同样明显，页表占用内存，此时虽然没有内存碎片，但存在页内碎片（比如进程大小5kb，页面大小4kb，会占用两个页面，第二个页面只用到1kb，剩下3kb就是业内碎片。

而**分段存储管理**和分页的核心区别在于快的大小不固定——分段按照进程的逻辑结构来划分的，比如一个进程分为“代码段、数据段、堆栈段”，每个段的大小由逻辑结构决定，段的大小不固定。方便代码复用和保护。 

常考的八股就是：分页分段的区别，段页式存储管理

### 虚拟内存（重点）
当物理内存不够，操作系统将部分暂时不用的内存数据，swap到硬盘中，腾出物理内存给正在运行的进程，从而实现“多个大进程同时运行。从而提高内存利用率，突破物理内存的限制。


# 计算机网络
计算机网络的**本质**是“将地理上分散的、具有独立功能的计算机，通过通信设备和线路连接起来，由完善的网络软件（协议）实现资源共享和信息交换的系统”

## 组成部分

### 网络硬件（了解即可）
**硬件**是计算机网络的物理载体，没有硬件，就没有网络的物理连接，核心掌握常用硬件的功能。
1. **终端设备**（终端节点）：最基础的硬件，是网络的“使用者”，比如电脑、手机、平板、服务器（提供服务的终端）。核心作用：发起网络请求（比如浏览器访问网页）、接收网络响应（比如接收网页内容）。
2. **通信设备**（连接节点）：负责连接**终端设备**，转发数据，是网络的“桥梁”，面试高频重点。
        
  - **交换机**（Switch）：连接同一局域网内的终端设备（比如家里的路由器自带的交换机），基于MAC地址转发数据，核心作用是“在局域网内传递数据”，不会转发广播包到其他局域网。

  - **路由器**（Router）：连接不同的**局域网**（比如家里的局域网和运营商的广域网），基于IP地址转发数据，核心作用是**“跨网段通信”**，是互联网的核心连接设备（比如我们上网，本质是路由器将请求转发到互联网）。
  - 补充：网卡（Network Card）：每个终端设备都有的硬件，负责将计算机中的数据转换成电信号/光信号（便于在线路中传输），同时接收外部的电信号/光信号，转换为计算机能识别的数据。

3. **传输介质**（传输通道）：负责传递数据的“线路”，分为有线和无线两类。
        
  - 有线介质：网线（双绞线）、光纤（传输速度快、抗干扰强，用于骨干网络）、同轴电缆（老式电缆，现在较少用）。

  - 无线介质：无线电波（WiFi、手机流量）、红外线（近距离传输，比如遥控器）。

### 网络协议
刚才介绍了硬件本身，**协议**规定了数据的传输格式、传输顺序、错误处理等规则。没有协议，不同厂商的设备无法通信（比如华为路由和小米路由器）无法通信。

1. **协议的核心特点**：约定俗成、标准化（比如**TCP/IP协议是全球通用的互联网协议**）、分层实现（不同协议负责不同层次的功能，互不干扰）。
2. 高频基础协议（先了解功能，不深入细节）：

  - **IP协议**：互联网协议，核心是“给每个终端分配唯一的IP地址”，负责跨网段的数据转发（比如路由器就是基于IP协议转发数据），属于“无连接、不可靠”协议（不保证数据一定能到达）。

  - **TCP协议**：传输控制协议，基于IP协议工作，核心是“**保证数据可靠传输**”（比如传输文件、网页，不允许丢失数据），属于“面向连接、可靠”协议（通信前先建立连接，通信后断开连接，确保数据不丢失、不重复）。

  - **UDP协议**：用户数据报协议，同样基于IP协议，核心是“**快速传输，不保证可靠**”（比如视频通话、直播，允许少量数据丢失，优先保证速度），属于“无连接、不可靠”协议。

  - **HTTP协议**：超文本传输协议，核心是“**浏览器和服务器之间的通信协议**”（比如我们打开网页，浏览器就是通过HTTP协议向服务器请求数据），基于TCP协议工作。

需要记住“TCP可靠、UDP快速”“IP负责寻址、TCP/UDP负责传输、HTTP负责应用通信”的逻辑，后面**分层学习**需要用到。

### 网络分层
计算机网络的核心设计思路是“分层”——将复杂的网络通信流程，拆分成多个独立的层次，每个层次只负责自己的功能，上层依赖下层，下层为上层提供服务，这样既降低了复杂度，又便于维护和升级。我们主要学习**OSI七层模型**：

- **物理层** ：负责物理介质的二进制信号传输。
- **数据链路层** ：负责同一局域网内的帧传输。
- **网络层 **：负责跨网域的路由寻址。
- **传输层**：负责端到端的数据传输。TCP、UDP。
-  **会话层 **：建立、管理、终止两个主机之间的通信会话
-  **表示层**：数据的格式转化、加密、压缩。jpg，json
-  **应用层**：为应用程序提供网络服务。http/https。
        

下层负责“物理传输、寻址”，上层负责“应用交互”。

### IP地址和端口
计算机之间要通信，必须知道“对方在哪里”，IP地址和端口就是用来“定位终端和应用”的核心标识。
1. **IP地址**：用于定位“终端设备”（比如电脑、服务器），相当于设备的“网络身份证”，全球唯一（比如192.168.1.1，是常见的局域网IP）。

  - **分类**：IPv4（32位，比如192.168.1.1，目前主流，但地址资源不足）和IPv6（128位，用于解决IPv4地址不足的问题，未来趋势）。

  - **补充**：子网掩码、网关：子网掩码用于区分“局域网IP”和“公网IP”，网关是局域网与外部网络连接的“出口”（比如家里的路由器IP就是网关）。

2. **端口**：用于定位“终端上的应用程序”（比如电脑上的浏览器、微信、QQ），相当于设备的“门牌号”，每个应用程序对应一个唯一的端口（0-65535，其中0-1023是知名端口，比如HTTP对应80端口，HTTPS对应443端口）。

3. 核心关联：通信时，必须同时知道“IP地址+端口”，才能准确定位到“某台设备上的某个应用”，比如浏览器访问百度，就是访问“百度服务器的IP地址+80端口”。

### 数据传输流程
发送方将数据从应用层向下传递，每经过一层，就添加该层的“协议头部”（封装）；数据通过传输介质、通信设备传输到接收方后，从下向上传递，每经过一层，就去掉该层的协议头部（解封装），最终将数据交给应用层。

例子：浏览器访问网页（浅度流程）：浏览器（应用层，HTTP协议）→ 数据交给传输层（TCP协议，封装TCP头部）→ 交给网络层（IP协议，封装IP头部）→ 交给网络接口层（封装MAC头部）→ 通过网线/WiFi传输 → 路由器转发 → 服务器接收 → 逐层解封装 → 服务器应用层处理请求 → 按相反流程返回数据 → 浏览器显示网页。
